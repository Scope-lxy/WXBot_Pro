01

接收和安全入队

监听回调或全局扫描

回调逐条复制纯数据；全局扫描返回一个会话的有序纯数据批次。wxautox Message 不离开 owner 边界。

->

识别方向与去重

native ID 相同才做强去重；hash 或正文相同不能删除两次真实出现的消息。机器人回声关联到对应 delivery，人工 self 则推进会话版本。

->

写 SQLite 后进入 FIFO

chat_events 是唯一事实源。扫描批次在同一事务提交，成功后才派发和建窗；图片先保存占位事实再下载补充。

v

语音正文还未出现

只对有时长的私聊，或已开启语音识别的群聊，在约 5 秒、10 秒后通过普通 GetAllMessage() 读取新快照。生产路径绝不调用 msg.to_text()；仍无正文就静默结束。

自己账号发出的消息

机器人 outbound echo 回调不推进版本。确认是手机手动回复时：写入 history、推进该会话版本，并取消尚未开始的旧 AI 气泡；本条不触发 AI。

02

路由和消费决策

这条入站应由哪种业务消费？素材投喂、关键词、AI 或跳过

素材优先

素材投喂

素材来源中的有效消息进入素材池，本条消费完即结束。

规则优先

关键词回复

私聊和群聊规则优先于普通 AI。文字、文件等依次作为可取消的独立意图提交。

范围不满足

只监听 / 黑名单 / 条件不符

记录必要运行信息后不调用模型。群聊还会判断是否需要 @ 机器人、是否允许 AI。

03

生成前补全与回复组装

建立回复任务

需要回复时建立 reply_job，绑定入站事件、会话版本和 15 分钟有效期；每个气泡再建立独立 delivery action。

->

按代次补齐可见尾部

窗口变为当前运行期可信可用后的首次回复读取当前窗口一次；没有标记时不读取，也不滚动深历史。

->

构造并生成回复

组合人设、近况、记忆、最近聊天、图片视觉笔记和本轮消息。模型输出再经过清洗、准入、必要时重写或固定兜底。

v

可选语音回复

满足触发条件时调用 TTS；成功发送则记录语音正文，TTS 或发送失败可降级文字。微信提交结果不明时不进行文字补发。

拆成独立气泡

显式换行优先，再按语义和长度拆分。第一条不额外延迟；后续气泡是否加固定间隔，分别由私聊和群聊配置控制。

04

发送、确认与中断恢复

每个气泡单独提交 UI owner

发送前登记 outbound echo，并核对目标子窗口和会话版本。不会使用不可中断的 SendMsgBatch。

->
气泡开始前版本仍一致？对方新消息或手机手动回复会立即推进版本
->

确认成功

只为实际发出的气泡写 history、回复统计和面板日志。语音以 [语音]正文 记录，多气泡用 ｜ 分隔。

版本已变化

已开始的单个气泡可完成；尚未开始的剩余气泡取消。取消内容不记为“已回复”。

已提交但结果未知

标记 uncertain，保留证据并禁止自动重发，避免真实好友收到重复消息。

进程中断

有效期内且未 claim 的任务可重新生成；遗留 inflight 转为 uncertain，同轮剩余气泡取消，绝不自动重发。

读图结论：“晚回复”通常是为了守住更重要的边界：先让独占维护安全结束、让上下文完整、让目标窗口确认正确，再发出仍属于当前会话的回复。

对应代码入口以 wxbot_core.py、feature/message_routing.py、core/wechat_ui_runtime.py、core/message_store.py 与 core/reply_delivery.py 为准。更新流程时，请同时更新本图与开发指南。
