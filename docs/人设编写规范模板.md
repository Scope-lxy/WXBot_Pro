# 人设编写规范模板

这份文档面向维护者编写基础人设和人设近况时参考。

## 先分清两类文件

- `data/prompt/<人设名>.md`：基础人设。放长期稳定的身份、关系、性格、表达方式和边界。
- `data/prompt/<人设名>-人设近况.md`：人设近况。放最近一段时间会变化的状态、关注点和想聊的话题。

简单说：

- 不会因为这周发生了什么就改变的内容，写进基础人设。
- 过几天、过几周就可能要改的内容，写进人设近况。

## 基础人设推荐结构

当前仓库自带模板文件：`data/prompt/模板.md`。

建议按下面这几个部分写：

1. `核心身份`：这个角色是谁。
2. `背景设定`：她来自哪里，长期处在什么生活状态。
3. `关系设定`：她怎么看待聊天对象，默认关系是什么。
4. `核心性格`：稳定的人格底色、行为倾向和明显不会做的事。
5. `表达风格`：说话语气、常用表达、明确避免的表达。
6. `行为原则`：遇到情绪、追问、靠近、冷淡时的处理方式。
7. `边界禁区`：绝不碰的内容和不接受的互动方式。

## 人设近况推荐结构

当前仓库自带模板文件：`data/prompt/模板-人设近况.md`。

建议固定用这四栏：

1. `最近的状态`
2. `最近在忙什么`
3. `最近想聊什么`
4. `接下来想做什么`

近况只写当前阶段的信息，不要把整个人设重新复制一遍。

## 编写原则

- 一份人设只讲一个稳定角色，不要混多套互相冲突的身份。
- 基础人设写长期规律，近况写短期变化，不要串层。
- 用能直接驱动回复的话来写，少写作者说明、少写抽象口号。
- 优先写“会怎么说、怎么做、怎么避开”，少写空泛形容词堆叠。
- 示例对话要短，重点是让语气可模仿，不是写成长篇剧情。
- 近况为空时就删除对应 `-人设近况.md`，不要留一个空文件占位。

## 不推荐的写法

- 把聊天对象的具体历史记录直接塞进基础人设。
- 把一次性的日程、情绪、事件写成永久设定。
- 同时写很多互相打架的要求，例如“高冷”又“句句热情主动”。
- 用大量规则把回复锁死，导致人设只会机械复读。

## 维护建议

- 改人设语气、关系、边界时，优先改基础人设。
- 只想让角色“最近像是在过某种生活”时，只改人设近况。
- 如果一次改动同时影响面板说明、模板或 Prompt 行为，记得同步更新 `README.md`、`docs/WXBot Pro 开发指南.md` 和这份文档。
