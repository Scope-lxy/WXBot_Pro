# 伪 BUG 记录

这份文档记录已经确认属于当前产品机制、不要再反复当成 BUG 上报的点。后续审查如果再次看到这些现象，先按这里的结论处理，除非用户重新定义产品目标。

## 已确认不是 BUG

- 远程面板登录后可以访问面板需要预览的本机图片，这是远程管理场景必须保留的机制。风险前提是面板账号泄露，不能简单当成功能缺陷。
- 邮件和 Webhook 配置会回传到浏览器，当前接受这个机制。它方便面板编辑已有配置，不作为本轮安全 BUG 处理。
- 朋友圈任务 AI 文案生成失败后可能停在“生成中”，这是当前异步生成流程的机制，暂不影响核心使用。
- 素材源消息写入聊天记录可以接受。素材投喂本质上也是和某个窗口发生的一次消息记录，不必默认排除出聊天记录。
- `wx_id` 会作为账号级数据目录名使用，这是当前账号隔离机制的一部分，不作为 BUG 处理。
- 私聊“对方发语音时”触发用语音回复，本质上依赖“语音转文字”。当前勾选这个触发后，保存配置会自动带起私聊语音转文字；如果仍然没有进入 AI 自动回复链路，优先排查微信自身转文字能力，而不是先怀疑面板开关不同步。
- `AI自动转发` 的“素材类型限制”当前属于预留机制：默认允许全部，同时隐藏 UI 控件；现阶段不要把“限制未生效”当成 BUG 记录。
- 直传视觉路径当前机制上就不返回图片理解摘要，因此也不存在“把摘要继续沉淀进后续上下文”的链路；不要把这类现象当成 BUG 上报。
- 朋友圈任务编辑图片后，不会自动让已有 AI 候选失效；这是当前产品机制。用户需要手动重新生成，系统会按最新图片重新生成文案。
- 定时消息执行记录里，“部分成功”当前按“成功”归类展示；它最多影响统计精确度，不影响实际发送结果，现阶段不作为 BUG 处理。
- 接口测试把 `vision` 结果写回配置后，不会立刻热同步到正在运行的 bot；通常用户改完接口也会顺手重测或重载，这个现象现阶段不作为 BUG 处理。
- 朋友圈任务详情里的图片缩略图删除按钮目前主要依赖 hover 态呈现，在触屏设备上交互不够理想；当前先按桌面优先处理，现阶段不作为 BUG 处理。
- AI 文案生成过程中，详情页的 `AI文案 / 原始文案` 仍可切换，可能出现短暂的模式闪回；当前不影响最终生成结果，现阶段不作为 BUG 处理。
- `vision` 能力当前按接口槽位 index 记录，不和 `sdk / url / model` 做强绑定；按当前使用习惯，用户改模型后通常会重测，这个风险现阶段不作为 BUG 处理。
- 轻量延后发送队列对同一个目标只保留最新一组待发送动作；同一目标在锁忙期间重复入队会覆盖前一次内容。这是当前产品设计，用来避免 UI 忙碌后堆积过期消息，不按“消息丢失 BUG”处理。
- 私聊消息去重现在以“同一会话 + 同一发送者 + 同一类型 + 同一内容”的短时间重复回调为准，不再按监听来源区分放行；这用于兜住同一条真实消息从不同入口进来时的重复处理，不按“连续消息被系统故意吞掉”处理。

## 已确认需要修复

- 面板点击“启动机器人”后，不能在后台实际初始化失败时仍然只提示成功。
- 顶部提示不能继续表达成“改配置必须关闭后重启”，应说明多数配置会运行中同步，异常时再重启。

## 待解释或后续再决定

- 配置保存失败提示：更好的做法是让底层保存函数返回具体错误原因，前端展示“哪个字段/哪个文件保存失败”，而不是统一只说“配置保存失败”。这属于体验优化，后续可单独排期。
