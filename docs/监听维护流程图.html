监听维护与 UI 调度流程图

黑名单模式由单一扫描泵公平发现未读，消息整批落库后再按需建窗；全部微信动作仍由唯一 UI owner 按 FIFO 执行。

查看消息处理图 使用说明 开发指南
唯一 UI owner
只有 owner 创建和使用 wxautox/UIA 对象；业务线程只传纯数据意图。
同类失败局部收敛
控件超时、会话不匹配、资料页失败只结束或延后当前任务，不重绑客户端。
固定与动态分治
固定对象低频校验补回；动态对象收到消息才补窗，同一目标合并，不重复建窗。
独占事务优先完整
通讯录批次和手动全量关系扫描不被聊天抢占；恢复聊天页后再按 FIFO 续处理。
01

启动与全局扫描

启动 UI owner

owner 线程创建 WeChat、读取当前账号、初始化监听器。wxautox 对象不能跨线程保存或使用。

->

先扫描并整批落库

黑名单模式只保留一个扫描任务；15 分钟内的恢复消息先等同会话扫描批次对齐，再与新消息走同一队列。非空结果立即把下一轮放到 FIFO 尾部，SQLite 整批成功前不建窗。

->

空扫描后放行固定窗口

首次空扫描后再补固定群聊和素材来源。白名单模式仍直接注册已配置对象。

02

动态监听与按需补窗

发现并保存新消息

固定回调逐条保存；全局扫描返回同一会话的纯数据批次，原子提交后才进入业务队列。

->
目标已有健康子窗口？同时校验当前窗口是否仍属于这个目标
->

复用并处理

刷新活跃状态，交给消息路由。发送前还会再次核对目标窗口，避免回复误投。

v

没有健康窗口

登记一个建窗任务

扫描链路不等待建窗；owner 稍后添加并验证子窗口，当前 runtime 已登记的窗口直接复用。

补窗暂时失败

延后、合并和轻量重试

先在 30 秒、60 秒后延后；之后在 600 秒待处理窗口内继续轻量重试。同一好友的新消息合并到既有任务。

已监听但无子窗口残留

受控关闭重建

只有这类明确残留状态允许关闭后重建。普通动态监听增删不重绑微信客户端，也不强清窗口。

v

扫描覆盖降级

返回少于扫描前未读、耗时达到 10 秒或数量达到 30 条时明确提示；已取得消息继续处理，第一阶段不自动 deep。

窗口恢复后的 tail

窗口从不可信变为可用时生成补洞代次；旧补洞成功不能清除恢复期间产生的新代次。

03

所有微信动作都走同一 owner

业务线程产出
纯数据意图
回复、关键词、文件、语音和 quote：每项独立、可在开始前取消。
好友申请和素材转发：一旦提交结果未知，持久化为 uncertain。
备注、标签同步和单人资料编辑：进入 owner 后保留窗口置前、搜索和鼠标焦点步骤。
图片、引用等媒体动作也等待 owner；不建立绕过队列的“高优先级下载”通道。
v

owner FIFO 执行

真实发送、窗口切换、资料页、素材读取都在 owner 中完成，并把明确结果回写给调用方。

->

目标窗口不能确认

尝试补窗；仍失败时登记监听窗口恢复任务。任务只保存窗口状态，不持有消息；宁可暂缓，也不基于错误窗口发送。

->

明确结果

成功才写成功日志与历史；取消、排队或未知提交不会伪装成已完成。

04

通讯录批次与关系扫描的独占边界

通讯录自动维护开始

正常批次固定 50 人，完整轮间隔 7 天。完整资料采集只在最小子进程运行，主进程持有 UI 协调权。

->

全屏障期间

从启动采集到 SwitchToChat 恢复完成：聊天路由、AI、媒体下载和后到微信意图全部等待；新消息只存纯数据 FIFO。

->

恢复聊天页后放行

采集完成或 300 秒硬超时后，必要时按 PID kill / taskkill 兜底，恢复聊天页，再按 FIFO 处理积压消息。

v

通讯录资料一致性

contacts.json 只保存真源资料；读改写使用路径锁和原子替换。展示名、发送目标只作任务运行快照，不写回档案。

手动全量关系扫描

也是连续、不可抢占的 owner 独占事务，不提供中途停止。1000 次滚动仅是失控保险，不是正常结束条件。

05

失败分级与恢复

普通业务失败

结束或延后当前任务

控件超时、目标不匹配、单个资料页不适用等，不能升级为客户端重绑。

监听器异常

先探活，再只重建监听器

现有客户端可用时只恢复监听。监听回调线程异常必须让运行健康状态变为不健康，不能静默失联。

明确客户端级失效

受控重绑或 watchdog

只有 Windows 1400 无效句柄、COM/RPC 断开等明确证据，才允许重绑。UI 卡死由专用 watchdog 以退出码 86 交给启动器恢复。

启动器的最后防线：用户点击停止不会自动启动；只有退出码 86 才计入恢复预算，滚动 30 分钟最多自动重启 3 次。超过预算时停在可排查状态，不进入短循环重启。

对应实现以 feature/listening.py、core/wechat_ui_runtime.py、feature/contacts.py、feature/contact_auto_collector_worker.py、wxbot_core.py 和 core/ui_restart_policy.py 为准。更新调度规则时，请同时更新本图与开发指南。
