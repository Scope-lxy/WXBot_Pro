# 自动加好友模块方案

## 目标

【自动加好友】是一个通用的好友申请模块，不绑定死某一种来源。第一期只开放“删除我的人”，后续可扩展到“群内成员”“手机号”等添加对象。

当前第一期能力：

- 从通讯录建档里读取带指定标签的联系人。
- 对“删除我的人”这类已有会话联系人，进入会话后点击 `发送朋友验证` 发起申请。
- 按添加对象维护多批申请文案；同一添加对象下所有启用文案合并后随机使用。
- 控制每日申请次数、申请时间段、申请间隔、重复申请策略、朋友圈权限和添加后的标签。

## 添加对象

添加对象是模块的第一层来源抽象。

| 添加对象 | 当前状态 | 候选来源 | 发送器 |
| --- | --- | --- | --- |
| 删除我的人 | 已开放 | 通讯录建档标签 | `conversation_verify_sender` |
| 群内成员 | 预留 | 群成员列表 | `message_add_friend_sender` |
| 手机号 | 预留 | 手机号名单 | `search_add_friend_sender` |

前端只展示后端下发的可用添加对象。第一期只展示“删除我的人”。

## UI 结构

模块位于【新好友】页内，标题为【自动加好友】，展示在【通过新好友】前面。

布局采用与【通讯录维护】一致的 6:4 结构：

- 左侧：申请文案、候选人。
- 右侧：自动发送申请参数。

### 左侧：申请文案

每个文案批次包含：

- 添加对象：当前仅“删除我的人”。
- 开关：控制这一批文案是否参与随机池。
- 申请文案：每行一条。

执行时按候选人的添加对象找到所有启用文案批次，把多批文案合并成一个池，然后随机抽一条。

没有默认文案。没有任何启用文案时，发送空验证消息。

### 右侧：自动发送申请

字段：

- 添加对象：当前仅“删除我的人”。
- 选择标签：标签多选控件，用于筛选“删除我的人”候选。
- 每天最多申请（次）。
- 可申请时间段：时间段组合控件。
- 每次申请间隔（分钟）：成功提交后生成带随机浮动的下一次运行时间。
- 重复申请策略：当天不重复、3天不重复、7天不重复、30天不重复。
- 朋友圈权限：不设置、仅聊天。
- 添加后的标签：申请提交时传给添加好友窗口。

不提供排除标签。

## 数据模型

账号级状态文件：

```json
{
  "schema_version": 1,
  "wx_id": "wxid_xxx",
  "settings": {
    "enabled": false,
    "add_object": "deleted_me",
    "include_tags": ["删除我的人"],
    "daily_limit": 20,
    "base_interval_minutes": 30,
    "allowed_time_ranges": ["09:00-22:00"],
    "permission": "不设置",
    "success_tags": [],
    "recent_duplicate_days": 7,
    "sender_kind": "conversation_verify"
  },
  "message_rules": [
    {
      "rule_id": "rule_xxx",
      "enabled": true,
      "object_kind": "deleted_me",
      "messages": ["你好，方便的话通过一下。"]
    }
  ],
  "candidates": [],
  "executions": []
}
```

说明：

- `add_object`：当前全局执行的添加对象。
- `object_kind`：文案批次匹配的添加对象。
- `include_tags`：第一期用于筛选“删除我的人”候选。
- `success_tags`：提交申请时传给添加窗口的标签。
- `permission` 为“不设置”时，不向 `AddFriendsWnd.send` 传 `permission` 参数。

## 发送器

### conversation_verify_sender

用于“删除我的人”。

流程：

1. 置顶微信窗口。
2. `ChatWith(target_name, exact=True)` 打开目标会话。
3. 校验当前会话名等于目标名。
4. 在当前会话消息里查找包含 `开启了朋友验证` 和 `发送朋友验证` 的系统消息。
5. 获取系统消息控件的 `BoundingRectangle`。
6. 只截取该消息区域截图。
7. 识别微信蓝色文字片段，兼容换行：
   - `发送朋友验证`
   - `发 / 送朋友验证`
   - `发送 / 朋友验证`
   - `发送朋 / 友验证`
   - `发送朋友 / 验证`
   - `发送朋友验 / 证`
8. 选择有效蓝色片段，并在片段内部带随机偏移点击。
9. 打开 `AddFriendsWnd` 后提交申请。

关键约束：

- 不使用固定屏幕坐标。
- 每次真实微信操作前置顶微信窗口。
- 如果识别失败或窗口被遮挡，重新置顶后再重试，不盲点。
- 点击点位不取严格中心，使用片段内部随机偏移。

## 调度规则

自动运行时：

- 必须开启模块开关。
- 必须在可申请时间段内。
- 不超过每日申请上限。
- 不命中重复申请策略。
- 到达 `next_run_at` 后才处理下一人。

手动“执行一次”：

- 仍然只处理 1 个候选人。
- 绕过时间段和间隔限制。
- 不绕过每日上限和重复申请策略。

## 实机验证结论

已验证：

- `瑞东（私人号）` 曾成功提交好友验证申请。
- `瑞东（私人号）`、`追梦瑞弟` 可通过当前会话系统消息找到 `发送朋友验证`。
- 当前微信版本没有把 `发送朋友验证` 暴露成可直接点击的 UIA 子控件。
- 稳定方案是：系统消息控件矩形 + 局部截图 + 蓝色文字片段识别 + 随机偏移点击。
- 窄窗口换行情况下仍可识别蓝色文字片段。

未开放但预留：

- 群内成员：后续接 `Message.add_friend`。
- 手机号：后续接 `wx.AddNewFriend(...)`。
