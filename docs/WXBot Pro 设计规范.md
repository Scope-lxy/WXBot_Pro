# WXBot Pro 面板设计规范

本文档记录当前面板已经形成的真实 UI 规则，后续改面板时以 `templates/static/dashboard.css` 和 `templates/dashboard.html` 的现状为准。它不是视觉重设计提案，也不记录单页业务文案。

## 产品气质

1. 面板是桌面优先的管理后台，核心目标是让配置、任务、状态和日志可扫读、可比较、可快速操作。
2. 首屏不做营销式大标题、插画、装饰渐变或大面积视觉氛围；进入面板后直接呈现可操作内容。
3. 视觉基调是“深色导航 + 浅色工作台 + 微信绿主操作”。页面应克制、清楚、密度适中，避免做成花哨卡片墙。
4. 后端能力可以复杂，但用户触碰到的界面必须稳定：按钮位置、卡片层级、空状态、反馈和移动端折叠规则不要随单页临时变化。

## 全局骨架

- 顶部栏固定高度 `56px`，使用深灰背景；品牌、账号和退出入口都在顶部栏内。
- 左侧导航桌面端固定宽度 `160px`，深灰背景，导航项用图标 + 短标题，选中态使用微信绿。
- 主内容区从顶部栏和侧栏让出空间，桌面端默认内边距为 `24px 28px`。
- 手机端不保留固定侧栏：导航通过顶部菜单按钮打开，主内容区改为自然长页。
- 底部日志面板是运行观察区，不要把普通页面反馈堆到日志面板里替代表单旁的即时反馈。

## 颜色与层级

当前色彩以 CSS 变量为唯一来源：

- 主操作 / 成功：`--primary #07C160`，hover 使用 `--primary-dark #06AD56`。
- 危险：`--danger #FA5151`，用于关闭、删除、高风险关闭态。
- 警告：`--warning #FFC300`，只用于需要留意但不阻断的状态。
- 信息：`--info #10AEFF`，用于中性信息提示。
- 页面背景：`--bg #F3F4F6`。
- 主卡片：`--surface-l1 #FFFFFF`。
- 二级面板：`--surface-l2 #F1F2F4`。
- 三级内容卡：`--surface-l3 #FFFFFF`。
- 空状态 / 轻提示底：`--surface-l4 #F7F8FA`。

不要为单个页面另起一套主色、渐变或大面积主题色。新增颜色必须能归入“主操作、危险、警告、信息、禁用、文本、边框、背景”之一。

## 形状与密度

- 全局圆角基准是 `8px`，普通按钮、输入框和小控件通常是 `6px`。
- 常规卡片用轻边框 + 轻阴影，不做强浮起、不做厚重阴影。
- 页面主要卡片 `.cfg-card` 使用白底、`8px` 圆角、`1px` 边框、轻阴影，内边距以现有变量为准：横向 `24px`，底部 `24px`。
- 二级卡片和任务详情区使用 `12px` 内边距；独立小卡片也优先用 `12px`。
- 不要新增圆角特别大的“胶囊卡片”或嵌套卡片。卡片可以包含表单区、列表区和详情区，但不要再把整页分区包成一层浮动大卡。

## 间距控制

当前面板的间距逻辑是“固定档位 + CSS 变量落地”，不是每个页面自由调数值。后续改 UI 时先选档位，再决定用哪个现有变量或组件结构承接。

- `8px`：行内小间隔、图标和文字、按钮组、紧凑列表项。
- `10px`：头部操作组、表单行内控件、卡片标题和状态之间的标准间隔。
- `12px`：同组内容块、二级卡片内边距、任务详情区和大多数列表间距。
- `14px`：较密集任务卡、规则卡或状态块内部的补充间距，只有现有组件已使用时继续沿用。
- `16px`：双栏 grid 间距、页面主块之间的标准间距、头部和正文之间更清晰的分隔。
- `20px / 24px`：只用于页面主卡片和主内容区这类外层结构，不下沉到普通 L3 内容项。

不要为单页新增 `5px`、`9px`、`11px`、`13px` 这类补丁值。发现不齐时，优先调整层级、容器和变量使用，而不是继续叠局部 margin。

## 排版层级

面板标题层级继续保持三层：

- `L1 页面 / 主卡片头`：使用 `.ui-head--page`，标题约 `16px / 800`，可带图标、说明和右侧操作。
- `L2 区块头`：用于卡片内二级区块，标题、说明和右侧控件按 `.ui-head` 现有规则排列。
- `L3 内容项`：用于任务卡、规则卡、开关行、参数行、素材项和记忆项。

标题只负责识别当前区域，说明只补充关键判断。能靠位置、分组和控件状态表达清楚的，不再追加长说明。

## 头部规则

- `L1` 结构固定为：图标 / 标题 / 说明 / 弹性空间 / 右侧控件。
- `L1` 说明默认单行省略，不能为了说明撑高整行；窄屏时允许头部换行，但控件仍要完整可点。
- 右侧控件只能放当前卡片直接相关的操作，例如新增、刷新、启用开关、筛选选择器。
- `L2` 没有必要时不加图标；不要为了“好看”给每个小标题补图标。
- 头部到底部分割线、分割线到正文的距离使用现有变量，不写页面私有补丁。

## 控件规则

- 普通输入框、下拉框、多选框触发器高度基准是 `36px`。
- `L1 / L2 / L3` 里的按钮高度分别按现有变量：`38px / 34px / 32px`。
- 按钮视觉类型固定：
  - 主按钮：绿色实底，用于启动、保存、确认、发布等主动作。
  - 次按钮：白底灰边，用于取消、查看、普通辅助操作。
  - 新增按钮：浅绿底 + 虚线绿边，用于添加规则、任务、文件等。
  - 危险按钮：白底红边或红色实底，只用于删除、关闭 CLI、停止等高风险动作。
  - 软按钮：浅蓝底，只用于次级信息类动作，不能替代主按钮。
- 操作按钮里已有 Bootstrap Icons 时优先用图标 + 短文案；纯图标按钮必须有明确 hover / title 语义。
- 开关统一使用当前 `.ui-switch` / `.switch-row` 风格，不要混入浏览器原生 checkbox 外观。
- 删除、选择文件、选择图片等短操作保持固定宽度，不参与挤占主信息空间。

## 表单与配置项

- 表单标签约 `13px / 600`，提示文案约 `12px`、灰色、常规字重。
- 输入框 focus 统一为绿色边框 + 轻绿色光晕，不写页面私有 focus 样式。
- 禁用态必须同时弱化文字、背景和边框，且保留布局尺寸，避免开关禁用后页面跳动。
- 名称、备注、正文、路径等可变长字段可以伸缩；开关、短数字、删除按钮、状态胶囊和短选择器保持紧凑。
- 下拉选择器优先使用现有统一箭头和高度，不恢复浏览器默认箭头。
- 多选控件优先复用 `.compact-multiselect`：触发器单行省略，弹层内搜索、选项、空状态和底部动作保持一致。

## 卡片、列表与工作台

- 任务类页面优先复用现有工作台结构：左侧列表 / 右侧详情，桌面端双栏，移动端单列。
- 双栏只使用现有三套变量：`equal 50:50`、`main 约 60:40`、`main-reverse 约 40:60`。不要再发明 `58:42`、`62:38` 这类页面比例。
- 工作台左侧列表桌面端可独立滚动，最大高度使用 `--ui-workbench-list-max-height`；移动端取消内部滚动，按自然长页展示。
- 规则卡、任务卡、素材卡的头部结构固定为：标题 / 状态 / 弹性空间 / 操作。下方再放摘要、标签和执行信息。
- 选中态使用浅绿底和绿色边框，不用强阴影或大面积高亮。
- 列表优先单行省略；宽度不足时先裁切文本，再换行，最后才改单列。

## 状态、反馈与空状态

- 就地反馈优先出现在相关卡片或相关列表附近，不用弹窗打断配置流程。
- 成功、错误、信息反馈使用 `.cfg-feedback-*` 或 `.page-inline-notice--*` 的现有颜色系统。
- 空状态使用浅灰 / 白底、虚线边框、紧凑高度；不要做大块空白占位。
- “没有数据”和“加载失败”必须区分：加载失败应显示错误反馈，不退化成空状态。
- 异步生成类流程先让任务入列表，再在原内容位置显示生成中或可重试状态，不额外制造复杂状态矩阵。

## 数据与状态页

- 指标卡保持紧凑网格，数字使用更高字重和等宽数字感觉，辅助说明保持小字号。
- 图表区域要给足可读高度，但不要用图表挤掉页面主要控制区。
- 图例、悬浮提示和分组筛选使用小控件，不要变成大按钮组。
- 状态总览类信息可以用浅灰底二级面板，但不要新增独立的“关键统计”大横幅。

## 聊天记录与记忆页

- 聊天记录区域可以保留微信式气泡：左侧白底、右侧浅绿、时间居中灰底。
- 记忆列表、联系人列表和聊天区属于数据管理界面，优先保证密度、滚动稳定和选择反馈，不要按纯展示页改成大卡片。
- 行内删除 / 编辑按钮可以 hover 后出现，但移动端必须仍能完成操作。

## 响应式规则

- `900px` 以下优先单列化双栏工作台，取消列表内部固定滚动，控件宽度可占满。
- `560px` 以下进一步压缩顶部栏和头部说明，说明文字可以隐藏或省略，但主操作不能消失。
- 移动端按钮允许换行或占满一行，不能出现文字挤出按钮、控件互相覆盖、右侧操作不可点。
- 不使用按视口宽度缩放字号的写法；通过布局换行、省略和控件重排解决窄屏问题。

## 新增 UI 前检查

新增或调整面板 UI 前，按顺序检查：

1. 它属于全局骨架、`L1`、`L2` 还是 `L3`？
2. 它能不能复用 `.cfg-card`、`.ui-head`、`.ui-btn`、`.form-control`、`.switch-row`、`.compact-multiselect`、`.ui-split-grid` 或现有工作台结构？
3. 它使用的是哪一档固定间距，是否能通过现有变量承接？
4. 它的颜色是否来自现有变量，而不是单页新主题？
5. 它在桌面端能否扫读，在 `900px` 和 `560px` 以下是否仍可操作？
6. 空状态、失败态、加载态和禁用态是否都在当前区块内就地反馈？
7. 每一处新增样式是否真的有用户体验收益，而不是为了让单页“看起来不一样”？
