# WXBot Pro 自用增强版使用说明

本文按当前面板与运行代码的实际行为整理，面向本地自用维护场景。它说明这套 fork 当前怎么安装、怎么启动、面板里哪些能力可用，以及哪些数据不要误删或误提交。

## 项目简介

WXBot Pro 自用增强版基于上游 `SiverWXBot Plus` 继续维护，核心用途是用 Windows 微信客户端做本地自动回复、监听、转发、记忆和任务管理。

当前重点能力：

- 私聊 / 群聊 AI 回复、关键词回复、自定义转发。
- 图片识别、语音转文字、语音回复、本地自动拆分回复。
- 多接口配置、聊天主备切换、接口视觉能力识别。
- Prompt、人设近况、会话记忆和模型可见历史统一组装。
- 通讯录建档、身份校准、素材转发、AI 自动转发、发朋友圈任务。
- 管理员工作台接管、发圈、转发和运行状态查看。

这是个人维护 fork，优先保证当前本地体验和代码整洁，不保证和上游仓库持续兼容。

## 安装部署

### 方法一：直接运行当前源码目录（推荐维护时使用）

环境要求：

- Windows。
- Python `3.12`。
- 微信 PC 版与 wxautox Plus 运行环境。
- 可用的大模型接口配置。

启动方式：

```powershell
.\打开软件.bat
```

`打开软件.bat` 会优先创建或复用 Python 3.12 虚拟环境，安装依赖并启动面板。图片压缩需要 `Pillow`，启动脚本会自动安装；复用旧虚拟环境时也会检查并补装。

如果当前 Windows 环境里没有 `ffmpeg` / `ffprobe`，启动脚本会首次自动下载 Windows 预编译包，并解到项目自己的 `venv\tools\ffmpeg\`。如果系统 PATH 已经有可用版本，则直接复用。

`wechat-cli` 本地只读数据工具默认禁用。它可以加速通讯录维护、私聊 / 群聊聊天记录自动补全和关系扫描，但存在微信风控和账号封禁风险；只有在状态页的 `wechat-cli 当前状态` 卡片确认风险并点击绿色 `开启 CLI` 后，启动脚本才会准备 `venv\tools\wechat-cli\`、安装工具并做安全初始化。初始化时如果发现多个微信数据库目录，不会自动猜测账号，会等待面板状态卡和机器人启动后的账号校验确认。

### 方法二：打包给另一份独立运行环境

适合需要把当前版本同步到另一台实际运行电脑：

```powershell
.\打包发布.ps1
```

产物默认输出到 `dist/WXBot_Pro.zip`。脚本只会打包 `core/`、`feature/`、`extension/`、`templates/`、`data/system_prompts/` 和启动所需的根目录文件，并附带本地 Python 3.12 runtime。`data/config/`、`data/prompt/`、`data/accounts/`、`wxbot_logs/`、`docs/`、`tests/`、本地 `venv/` 和 `.git/` 都不会进包。自动下载到 `venv\tools\ffmpeg\` 的 `ffmpeg` / `ffprobe` 也不打包；工作机首次启动时会按同一套规则补齐。

启动后默认访问 `http://127.0.0.1:10001`。如果端口被占用，会顺延到后续空闲端口，请以启动日志里打印的地址为准。

## 管理面板使用

### 面板账密

首次进入面板使用默认账号密码：

| 项目 | 默认值 |
|------|--------|
| 用户名 | `admin` |
| 密码 | `123456` |

账密保存在 `data/config/admin.json`，可在面板内修改。开启远程访问前，务必先改默认密码。

### 模型配置

模型配置用于保存聊天、识图、发圈、语音合成等接口。常用字段包括 API Key、URL、模型 ID、SDK 类型和是否启用。

当前聊天接口支持主备切换：

- 只影响默认聊天接口，不影响识图接口。
- 连续失败达到阈值后切到备用接口。
- 切到备用接口后会按固定间隔探测主接口，主接口恢复后自动切回。
- 保存 API 相关配置或重启机器人后，会从主接口重新开始计数。

白名单好友或监听群聊如果绑定了专属接口，优先走自己的绑定，不参与默认聊天接口主备切换。

### Prompt 配置

面板左侧 **Prompt** 用于维护基础人设、人设近况和 Prompt 预览。

- `基础人设`：定义角色、语气和回复边界。
- `人设近况`：给某份人设补充当前阶段状态，文件与基础人设一起保存在 `data/prompt/`，命名形如 `<人设名>-人设近况.md`。
- `Prompt 预览`：查看某个好友最终会发送给模型的系统 Prompt。

普通回复、素材文案、发圈文案和 Prompt 预览都会复用这里的人设上下文。你可以把这里理解成“统一的人设入口”，改完以后，多数依赖人设的链路都会一起生效。

### 初步测试 - 调用AI接口

1. 登录 Windows 微信，保持主窗口打开，不要最小化。
2. 回到面板点击 `启动机器人`。
3. 等待面板提示启动结果，也可以看底部日志。
4. 在手机微信上给管理员窗口发送 `/状态`，确认机器人运行状态。
5. 再发送 `/帮助`，确认管理员指令可用。
6. 用已监听好友或群聊发送普通消息，确认 AI 回复链路。
7. 测试完点击面板上的 `停止机器人`。

面板日志按处理严重程度和运营观察价值分层：

- `INFO`：正常流程和过程流水，例如收到消息、命中规则、排队、读取进度、会话记忆更新、允许的静默策略、轻量延后监听与恢复。
- `SUCCESS`：产生明确运营效果，或关键节点已经完成，例如建档 / 通讯录自动维护当前批次成功、备注修复成功、微信标签同步有成功、关键词回复成功、定时消息 / 素材转发 / AI 自动转发 / 自定义转发成功、好友申请发送或通过成功、配置保存成功。
- `WARNING`：任务实例或局部动作失败，但机器人还能继续运行，例如定时消息 / 素材转发 / AI 自动转发失败、微信标签同步全失败、备注修复失败、轻量延后监听等待超过 600 秒、回复 / 语音回复触发上限首次命中、API 错误或轮数超限提示发送失败。
- `ERROR`：整体能力受损，需要重启、重建或重新初始化，例如微信监听器初始化失败、监听器自动恢复失败、核心监听线程异常退出。

日常观察机器人运行效果优先筛 `SUCCESS`；排查问题优先看 `WARNING` 和 `ERROR`。`INFO` 里的普通消息处理、记忆提取、轻量延后自愈和主动配置的静默策略通常不需要处理；回复上限类只在同一统计窗口首次命中时记录 `WARNING`，主要用于观察当前配置是否够用。

日志降噪只处理预期内的高频事件：上限类首次提醒后不重复刷屏，语音转文字只记录最终未识别结果；API 错误、图片下载 / 保存失败、发送失败和初始化失败仍会逐次记录，方便排查真实问题。

如果日志显示初始化微信监听器失败，优先重启微信和面板；仍失败时再检查微信版本、窗口状态和屏幕缩放。

### 初步测试 - 不需要调用AI接口

如果暂时不想配置模型接口，可以先测试关键词回复或自定义转发。

#### 方式一：测试关键词回复

1. 进入 **私聊监听** 或 **群组管理**，添加要监听的联系人或群聊。
2. 进入 **关键词回复**，开启私聊关键词或群聊关键词。
3. 添加一条规则，关键词可写成 `测试；试用`、`测试,试用` 或分行输入。
4. 回复区可只填文案，也可同时附带本地文件。
5. 如果测试的是群聊关键词，且不希望同时调用 AI，可在 **群组管理** 勾选 **只监听不 AI 回复**。
6. 如果测试的是私聊关键词，不要勾选 **私聊只监听不 AI 回复**；私聊只监听当前会直接跳过关键词回复。
7. 启动机器人后，从监听来源发送包含关键词的消息。

关键词监听的来源依托于 **私聊监听** 和 **群组管理** 中设置的监听对象，请先配置监听，再测试关键词。

#### 方式二：测试自定义转发

1. 进入 **私聊监听** 或 **群组管理**，添加来源联系人或群聊。
2. 如果不希望来源消息触发 AI 自动回复，勾选 **只监听不 AI 回复**。
3. 进入 **自定义转发**，开启规则。
4. 新增一条关键词转发、固定发送人转发或无差别转发规则。
5. 填写转发目标，例如另一个联系人、群聊或文件传输助手。
6. 启动机器人后，从监听来源发送符合规则的消息。

若规则勾选「全部来源」，来源依托于「私聊监听」和「群组管理」中设置的监听对象，请先在对应页面配置监听对象后再使用。

### 管理员配置

管理员窗口建议使用 `文件传输助手` 或自己的小号。管理员窗口是运行控制台，不再承担所有面板配置。

管理员前台模式有 `空闲 / 接管 / 发圈 / 转发` 四种，同一时间只保留一个前台模式。接管好友后，好友新消息会同步到管理员窗口，管理员普通文本和图片会直接回给当前接管好友。

常用指令和状态口径统一放在下文的“消息指令调用参考”，这里不重复展开。

#### 数据图表统计

状态面板不再单独展示“关键统计”卡片，今日统计统一放在“数据图表”顶部：`全部API调用`、`聊天API调用`、`收到消息`、`回复消息`、`活跃好友`、`活跃群聊`。

今日统计来自 `data/config/runtime_metrics_v1.json`，和趋势图、鼠标悬浮提示、底部图例使用同一套小时级统计口径；机器人未运行时也会显示当天统计数据，当天没有记录时显示 `0`。`全部API调用` 包含机器人向 AI 大模型和正式 TTS 模型发出的真实请求；面板测试、Prompt 预览、语音转文字等非业务请求不计入。`聊天API调用` 统计为了回复当前聊天而发起的聊天模型请求，包含 `final_reply.md`、轮数超限的 `closing_reply.md`，以及图片转文字辅助识别这类回复链路中的中间请求；不包含素材判定、素材附加文案等非聊天回复请求。

状态页还会在 `wxautox4 授权状态` 下方显示 `wechat-cli 当前状态`。默认关闭时显示红色提示条，左下角按钮是绿色 `开启 CLI`，点击前会弹出风控确认；开启后可用状态显示绿色提示条，左下角按钮变成红色 `关闭 CLI`，关闭时不再二次确认。可用且开启时，通讯录维护、聊天记录自动补全和关系扫描等功能会优先使用本地只读插件；不可用时，会显示原因和 `尝试修复`。右上角 `检查更新` 只检查并提示是否有新提交，不会自动更新工具。

### 私聊监听配置

私聊有两种监听模式：

| 模式 | 说明 |
|------|------|
| 白名单模式 | 只监听列表中的好友。填写微信里显示的备注名或昵称。 |
| 黑名单模式 | 全局监听未读红点消息，列表内对象不处理。 |

白名单好友可单独绑定人设、聊天接口和语音接口。未进白名单的私聊走全局配置。勾选 **只监听不 AI 回复** 后，私聊消息仍会被记录，也会继续参与自定义转发、素材转发等非回复流程；但不会触发关键词回复、轮数超限结束语或聊天模型回复。当前私聊只监听的优先级高于除 **自定义转发** 之外的其他回复路径。

#### 全局模式过滤免打扰

全局监听模式下可勾选 **不监听微信免打扰**。开启后会忽略微信里设置了免打扰的私聊窗口。当前全局监听采用轻量按需补窗，不再高频巡检子窗口；同一联系人短时间接管失败时，后续消息会先合并到延后任务里，减少微信列表反复滚动。如果出现全局监听异常，优先检查 Windows 屏幕缩放是否为 `100%`，再重启微信和面板。

#### 启用私聊图片识别

图片回复按最终回复接口是否支持视觉能力分两条路径：

- 支持视觉：直接把图片传给回复接口。
- 不支持视觉：生成或复用结构化视觉笔记，再交给主回复模型生成最终回复。

无论最终回复走哪条路径，机器人都会先尝试生成结构化图片摘要并写入本地记忆，用来支持后续追问图片上下文。因此即使回复接口本身支持视觉，也可能看到一次辅助识图调用。

同一张图在相同上下文、识图模型和识图 Prompt 下会复用视觉笔记缓存；切换识图模型或 Prompt 后会重新生成。

发送给 AI 的图片会先生成一份本地压缩副本，原始微信下载文件不会被改动。压缩副本统一放在 `wxauto_save/compress_images/`，机器人启动时会按【其他配置】里的自动清理缓存设置处理 `wxauto_save/` 缓存文件，默认保留 30 天，也可以关闭自动清理。

私聊图片会进入连续消息合并队列。只发图片时，机器人会在合并等待后围绕图片回复；先发图再补文字，通常会合并成同一轮图文消息；如果先发文字、过一会儿再发图，图片会作为下一轮结合最近聊天记录理解。多张图片最多合并 `9` 张。

图片还会最多保留 10 分钟作为最近图片上下文，用来桥接“刚发图后又追问”的场景。成功发送图片相关回复后会清掉这份短期上下文，后续继续聊同一张图时主要依赖聊天记录里的图片描述。

#### 处理语音消息和语音回复

私聊和群聊的 **内容识别** 卡片里，`处理语音消息` 控制机器人是否消费微信语音消息。该功能依赖微信自己的「语音自动转文字」结果，优先读取 wxauto 官方语音转文字接口返回的正文。

私聊语音如果刚收到时只有时长、暂时没有文字，机器人会先尝试微信语音转文字；如果仍未就绪，会每隔约 `5` 秒对这条语音重新尝试转文字，最多重试 `3` 次；第 3 次会先真正重试，仍没有识别结果才静默忽略，并只记录最终未识别的 `INFO` 日志。待识别语音会在当前连续消息批次里占住原始位置；如果合并等待先到，会先暂缓关闭批次，等语音识别成功或最终静默失败后再继续。只有识别出正文的语音会写入记忆并参与 AI 回复；未识别语音、微信语音 XML 占位和语音失败状态不会进入 AI 上下文，也不会额外发送失败提示。群聊语音当前不做延后重试，只有微信已经给出文字时才进入后续处理。

如果同一批私聊里有多条语音，只要其中有成功识别出的正文，机器人会用成功识别的语音内容正常触发 AI；同批里未识别或失败的语音会被丢弃，不会再额外发送失败兜底。

私聊语音回复支持两种触发：

- 收到好友语音。
- 命中语音请求关键词。

勾选收到语音触发时，保存配置会自动开启私聊处理语音消息。语音回复依赖 TTS 配置和 `ffmpeg` / `ffprobe`；合成失败时会降级为文字回复。

#### 自动拆分回复

自动拆分回复在本地发送层执行，不要求模型输出特殊拆分标记。AI 已经显式换行的内容会原样多条发送；没有换行时，只有整段超过单条最大字数才会按自然边界拆分。超过最多发送条数后，系统会尽量合并得自然、均衡。

私聊连续消息会先按“连续消息合并等待时间”等待好友停顿；这个能力强制开启，可设为 `1 ~ 60` 秒，默认 `20` 秒。设为 `1` 秒时接近即时回复，但仍会走同一条聚合链路。如果这一批包含图片，会按基础等待时间的 `2` 倍等待停顿，最多 `120` 秒，方便把紧跟着的说明文字一起带上。如果好友一直发送，系统会按内部最大等待时间先封口回复一轮，默认约 `60` 秒，最高随设置到 `180` 秒。

新消息会进入下一轮。普通 AI 回复如果已经开始拆分发送，同一好友又发来新消息，或你从手机微信等设备手动发出 `self` 消息，机器人会停止上一轮剩余气泡，避免继续发旧话题；轮数超限结束语和 API 错误提示会尽量保证送达。手动 `self` 会写入聊天记录但不会单独触发 AI；之后好友再发新消息时，机器人会重新进入正常 AI 回复流程，并把这条手动回复作为我方历史发言带入 `history`。

### 群组管理

群聊支持监听、AI 回复、关键词回复、自定义转发、欢迎语、图片识别、处理语音消息和语音关键词回复。

勾选 **只监听不 AI 回复** 后，群消息仍会被监听、记录并参与关键词回复和自定义转发，但不会调用聊天模型。面板会自动保持群聊监听开启，并临时禁用仅被 @ 时回复、回复时 @ 对方等依赖自动回复的选项，避免配置互相打架。

#### 群聊图片识别

群聊图片识别采用“先缓存、后按需识图”的机制，避免每张群图都消耗视觉 token。

- 群里收到图片时，只下载图片并缓存到该群的最近图片上下文，不会因为这张图片本身主动调用视觉模型。
- 最近图片上下文有效期为 10 分钟；同一个群的新图片会覆盖旧图片。
- 10 分钟内，任意群成员后续触发 AI 回复并明显在问图时，机器人会使用这张缓存图片。A 发图、B 再 @ 机器人问图也可以命中。
- 成功发送图片相关回复后，会清掉该群的最近图片上下文，避免下一轮重复消费。
- 如果后续消息不像是在问图，例如只问天气，机器人会走普通群聊文本回复，并保留图片上下文直到过期或被新图片覆盖。

问图判断偏覆盖优先。出现 `图`、`照`、`截`、`屏`、`票`、`单`、`image`、`photo`、`screenshot` 等视觉对象词，或出现 `看`、`读`、`写`、`识别`、`解释`、`翻译`、`描述`、`分析`、`提取`、`read`、`explain`、`translate` 等动作词，通常会触发看图。`what is / what does` 这类英文泛问句需要同时带 `this / that / above` 等指代词才会触发。

群聊开启“仅被 @ 时回复”时，未 @ 的图片只进入最近图片上下文，不触发 AI。未开启“仅被 @ 时回复”时，图片本身也仍然只缓存不识图；后续文本消息命中问图意图时才会消费。

### 新好友

新好友页支持：

- 自动通过新好友。
- 自动修改备注和标签。
- 新好友自动回复。

备注规则可配置前缀、后缀、是否包含原始昵称和时间戳。微信标签必须是当前微信里已经存在的标签。

### 通讯录维护

通讯录页用于读取微信联系人并保存到 `data/accounts/<wx_id>/contact_profiles/contacts.json`。使用 wechat-cli 本地快照时，会自动过滤公众号、群聊、企业微信 / openim、文件传输助手、系统号和空昵称等非普通联系人；如果状态页禁用了 `wechat-cli`，这里会直接走微信界面读取。

当前入口：

- `立即建档`：手动建档入口。CLI 开关开启、工具可用且账号已校验时，优先读取本地基础通讯录并合并进通讯录档案；CLI 禁用或不可用时回退微信界面分批读取。
- `停止建档`：停止后续建档，当前批次会先完成。
- `备注修复`：先弹出预览窗口，只处理没有备注且命中规则的联系人。
- `手动校准`：手动选择本地旧名字并输入新备注 / 昵称，立即合并聊天记录、会话记忆、关系扫描记录和相关配置；这个操作不读取微信通讯录。

页面顶部会显示当前账号的建档联系人、重复昵称、待修复备注和等待校准数量。`等待校准` 来自身份校准：当通讯录维护发现某个联系人可能改了备注、昵称或微信号，但无法高置信自动判断时，会在 `手动建档` 卡片内显示待处理表格。

身份校准表格展示 `新资料 -> 原资料 -> 依据 -> 操作`：

- `合并`：确认是同一人，系统会合并聊天记录、会话记忆、关系扫描记录和相关配置。
- `忽略`：确认本组候选不需要处理，后续同一组候选不再提示，不会合并或删除本地资料。

如果已经在微信里手动改了好友备注，并且明确知道旧名字和新名字是同一人，可以直接用 `手动校准`。它不等待下一次通讯录维护，适合把刚改名的本地资料马上迁到新备注 / 昵称下。

能自动判断为同一人的情况会直接合并，不进入表格。主要规则是：微信号 / wxid 相同、备注相同且唯一，或无备注时 `昵称 + 来源 + 添加时间` 相同且唯一并且只是微信号 / wxid 变化。昵称本身不作为独立强判断依据。

身份校准不会在每条消息里扫描通讯录。它跟随通讯录读取触发：自动维护、手动建档、备注修复成功后都会更新通讯录内嵌的校准状态。如果好友刚改名而通讯录还没维护到这个人，短时间内可能先出现新名字资料；下一次维护读到变化后再自动合并或进入等待校准。

页面提供三栏只读查看器：`微信号 -> 标签 -> 联系人列表`。开启 CLI 后，`wechat-cli` 只能维护昵称、备注、wxid 等基础资料；地区、来源、添加时间、标签、个性签名等完整资料仍以微信界面自动维护为准。CLI 基础资料同步只在 CLI 开启时触发：通讯录为空或距离上次同步超过面板 `每轮维护间隔` 时自动跑一轮；它不占用微信界面，也不会标记 UI 全量维护完成。自动维护开关开启时，后台维护仍通过微信界面分批读取完整资料。

开启 CLI 后，关系扫描会优先使用 `wechat-cli` 读取最近会话：自动扫描约 `6000` 秒读取最近 `1000` 个会话，手动立即扫描读取最近 `1000` 个会话，手动全量扫描最多读取 `10000` 个会话。禁用 CLI 时，手动扫描回退微信界面读取；后台自动扫描只轻量读取当前会话列表，不滚动、不抢锁，微信正忙就跳过本轮。关系判断只看会话最后一条消息是否命中删除 / 拉黑提示，不会搜索旧历史来主动扩大命中范围。

### 关键词回复配置

关键词回复支持私聊和群聊。关键词监听的来源依托于 **私聊监听** 和 **群组管理** 中设置的监听对象，请先配置监听对象。

一条规则可以包含多个关键词别名，支持用 `；`、`,`、中文逗号或换行分隔。回复内容可以是文案、本地文件，或二者组合；同时配置时会先发文案，再按顺序发送附件。单条规则最多附带 `9` 个文件。

### 自定义转发

自定义转发支持：

- 关键词转发。
- 固定发送人转发。
- 无差别转发。

普通转发只按规则把消息转给目标，不影响关键词回复和普通 AI 回复。勾选 `命中后转发给管理员处理` 时，会暂停该好友 AI 自动回复，并把消息转给管理员窗口；这条规则优先级高于关键词回复。

### 素材转发

素材转发用于把微信原生素材主动转发给好友，例如链接、小程序、图片等。它尽量保留微信原生消息样式，不是发送裸 URL。

当前页面结构：

- `任务列表`：管理单次任务、循环任务和系统卡片 `AI自动转发`。
- `素材来源`：配置从哪些微信会话收素材。
- `素材管理`：查看素材池、停用 / 恢复素材、维护素材归属和备注。

#### 素材转发

任务规则：

- `单次任务` 固定发送一条具体素材；素材来源 / 素材类型只作为筛选器。
- `循环任务` 从当前筛选范围里随机选材；素材来源 / 素材类型会限制随机候选。
- `附加文案` 支持 `无文案 / 自定义 / AI 文案`。
- 选择 AI 文案时，普通素材转发任务和 `AI自动转发` 共用“统一文案”生成层；最终文案会参考基础人设、人设近况、会话记忆、近期聊天、素材内容和转发目标。
- 发送目标必须能从当前微信号的本地通讯录档案中解析。

AI 自动转发：

- 系统卡片只保留 `判定周期（分钟）`、`判定门槛（条消息）`、`每天最多转发（次）` 3 个配置项。
- 只针对当前有真实新消息的活跃私聊。
- 同一检测窗口内，只有 `判定周期` 和 `判定门槛` 都满足时，才触发 1 次新的 AI 判定。
- 如果消息门槛先达到，就继续等时间到；时间到了以后，即使后面没有继续来新消息，也会补触发这 1 次。
- 新消息按对方任意私聊消息计算，表情也算。
- `每天最多转发（次）` 只限制 AI 自动转发对单个好友当天成功发送的次数，不影响普通单次 / 循环素材转发。

任务工作台：

- `定时消息`、`素材转发`、`发朋友圈任务` 共用右侧 `任务队列与执行记录` 卡片。
- `定时消息` 显示 `等待发送 / 发送记录`。
- `素材转发` 显示 `等待转发 / 转发记录`。
- `发朋友圈任务` 显示 `等待发布 / 发布记录`；点 `发布` 后进入等待发布，点 `取消` 后回到待确认。
- `关键词回复`、`自定义转发`、`定时消息`、`素材转发`、`发朋友圈` 这 5 个双栏页面复用同一套工作台外壳；桌面端左侧列表在卡片内独立滚动，右侧详情保持同屏，手机端按自然长页展开。

#### 随机消息

随机消息用于在时间窗口内随机发送普通文本或本地文件。当前只保留一个 `时间窗口` 输入，不再拆成开始时间和结束时间。

#### 定时消息

定时消息使用 `年月日 + 时间` 控件。内容模型统一为最多 `1` 条文案和最多 `9` 个本地文件；发送顺序固定为先文案、后文件。普通定时消息和随机消息会优先使用已监听的聊天子窗口发送，找不到时再回退主微信窗口。

#### 发朋友圈任务

当前只保留统一的 **发朋友圈任务**：

- 定时发布：选择 `年月日 + 时间`。

- 点 `添加任务` 后，只要有文案或图片，会立即进入左侧任务列表。

- 发圈文案生成有图片时走所选发圈接口的图片直传能力，不走辅助视觉转述路径；管理员 `/发圈` 和面板发圈任务使用同一套通用图片直传请求。

### 定时启停

定时启停用于配置机器人自动开启和关闭。涉及微信窗口和后台线程，改动后建议通过面板日志确认真实状态。

### 记忆管理

记忆管理分两层：

- 聊天记录：保存原始对话上下文。
- 会话记忆：结构化长期记忆，以 JSON 作为唯一真源。

当前面板里的“带入最近聊天”只配置一个数字：`最近 N 条`。`N` 支持 `1 ~ 200`，默认值为 `50`。系统会按真实聊天顺序带入最近 N 条可见聊天消息，不区分好友、群成员或机器人回复；微信时间分隔线只作为下一条消息的发送时间，不占条数。

AI 可见历史会统一做语义净化：图片、视频、文件不会把本地绝对路径直接带给模型。图片会以 `[图片]` 进入上下文；有视觉笔记时，会附带图片描述、可见文字和关键细节。语音只把转写正文带给模型，不带 `[语音]` 标签或语音时长，避免模型模仿标签污染回复。链接、小程序、视频、名片等会保留必要类型提示，视频会保留时长但去掉“下载”按钮字样。

#### 上下文自动补齐

聊天记录配置里有两个自动补齐开关：

- **自动补最近上下文**：默认开启。私聊或群聊准备进入 AI 回复前，机器人会按需校准最近上下文；同一会话成功补洞后约 `300` 秒内默认不重复补。私聊只有启动后的首次回复、恢复或身份迁移后的首次回复、当前好友消息不在本地记录尾部等强理由时才会补洞；不会因为单纯过了冷却时间就周期性补。开启 CLI 且账号已校验时，会优先按“带入最近聊天”参数读取最近 `60 ~ 210` 条本地历史；禁用 CLI 时直接读取当前微信窗口已经渲染的最近消息，UI 路径内部最多取 `30` 条。这个过程只补缺失记录，不整套替换聊天记录。
- **补上下文时允许滚动微信窗口**：默认关闭。开启后，只有低风险补洞仍无法对齐时，才会滚动当前微信窗口尝试读取更多历史，内部最多取 `50` 条，约 `60` 分钟冷却。这个开关属于高风险 UI 补洞，适合确实需要补较大断层时开启。

微信列表里的未读红点本身不会单独触发补齐；只有机器人准备回复这个私聊或群聊时，才会在发送给 AI 之前尝试校准上下文。CLI 补洞如果遇到同名私聊联系人，会先用最近会话和最近 `4` 条锚点消息做消歧；群聊补洞会用本地 `wechat-cli sessions` 找到对应 `@chatroom`，重名群需要带发送人的锚点消歧。找不到目标、目标不唯一、读取失败或微信锁繁忙时，会跳过本轮补洞并继续原回复流程，只是这一轮可能沿用当前已有聊天记录。

自动补齐会过滤“语音未识别”占位，并阻止近 `10` 分钟内同方向、同类型、同内容的重复记录再次写入。子窗口监听或全局监听识别到你自己从手机等设备发出的 `self` 消息时，会先排除机器人自己回复的回显，再直接写入聊天记录、停止该好友当前普通 AI 回复，但不触发新的 AI；普通好友文字/语音仍由私聊处理队列写入，只有轻量延后监听等待超时放弃时，才会兜底保存暂存的普通文字和已识别语音。

低风险补齐的可见消息读取偶尔会受微信 UI 影响变慢；超过约 `20` 秒会记录慢操作告警，方便观察微信 UI 卡顿。冷却中、微信锁繁忙这类正常让路不会刷日志，真正需要关注的是“补洞失败”或高风险读取异常。

补洞日志按数据来源显示：CLI 成功时通常只看到 `上下文 CLI 补洞完成，补入 N 条`；CLI 失败并切换到微信窗口读取时，会先显示 `上下文 CLI 补洞失败，原因：...；已切换微信 UI 兜底`，再显示 `上下文 UI 兜底补洞完成，补入 N 条`。常见 CLI 错误会尽量转成中文原因，方便直接判断是未初始化、账号绑定缺失、目标重名还是读取超时。

推荐先从较小上下文开始调，确认回复稳定后再逐步加大记忆规模。

#### 记忆查看

会话记忆页会同时显示：

- 已有会话记忆的对象。
- 只有聊天记录、还没有会话记忆的对象。

后者可以直接手动新增第一条记忆，也可以点击“马上提取记忆”初始化。手动提取会先弹出提取结果预览，确认后才真正保存；单次最多分析最近 `500` 条聊天记录。后台自动维护只处理新增聊天记录，达到阈值或超过间隔才会触发。

如果微信号、对话窗口、聊天记录或会话记忆加载失败，页面会在原位显示错误提示，并要求重新选择有效账号。

### 其他配置

#### 语音合成接口

模型配置页提供语音合成接口卡片，可配置接口名称、API Key、语音模型、音色和试听文案。语音模型下拉框保留 4 个豆包选项：`豆包语音合成 2.0 标准版（seed-tts-2.0-standard）`、`豆包语音合成 2.0 高表现力版（seed-tts-2.0-expressive）`、`豆包语音合成 1.0（seed-tts-1.0）`、`豆包复刻/设计音色 2.0（seed-icl-2.0）`；声音复刻和声音设计音色都走 `seed-icl-2.0`。只有 `seed-tts-2.0-expressive` 会附带上下文语义字段，其他模型不会发送上下文扩展字段。试听缓存落到 `data/cache/tts_preview/`，正式语音缓存落到 `data/cache/tts/`。

#### 启用发送延迟

发送延迟用于模拟人工回复节奏。当前可配置首条回复最小 / 最大延迟，以及拆分消息发送延迟。拆分消息发送延迟只影响拆分后的后续消息。

#### 自动清理缓存

自动清理缓存用于控制 `wxauto_save/` 里的微信下载缓存和 AI 处理缓存保留多久。可选项为 `不清理 / 7天 / 30天 / 90天 / 180天 / 360天`，默认 `30天`。

这个设置只影响缓存文件，不会删除聊天文字记录、会话记忆、配置或账号数据。缓存不是长期数据真源；如果希望长期保留某些原始图片、视频或文件，应单独保存到自己的资料目录。

#### 接口调用失败固定回复

当 AI / 模型接口失败时，可发送固定回复；留空则静默不回复，避免把原始报错发给用户。

该固定回复可勾选 **只回复一次**。勾选后，同一好友或同一群内同一发言人在当前回复循环窗口内只提示一次；窗口重置时间跟“超出次数限制固定回复”的回复循环规则一致。

#### 超出次数限制固定回复

私聊回复轮数限制按好友分别计数。超过上限后可选择：

- `AI自动生成`：基于人设、人设近况、会话记忆和最近聊天生成一句结束语。
- 手动固定回复。
- 静默不回复。

如果轮数超限结束语在生成时本身又遇到接口报错，会回退到上面的 **接口调用失败固定回复**；该项留空时继续静默。

轮数计数保存在 `data/config/reply_count.json`。

语音识别失败不再提供单独固定提示。当前仅把微信语音消息中精确识别为 `语音未能转换`、`语音转换失败`、`语音识别失败` 的状态当作失败；失败语音按“没有有效输入”处理，静默忽略，不写入 history，也不触发 AI 回复。

#### 自动清洗回复

发送前清洗会移除模型思考标签、时间戳、回复标签、回复开头的 `[语音]`、明显 AI 元话术，以及模型常见的语气 / 动作提示。被 `（）`、`【】`、`[]`、`「」`、`『』` 或 `* *` 包裹的片段，只要旁边还有正文，就会在发送前清掉；整条回复只有一个短包裹词时会保留，例如 `（好）`、`【收到】`、`*抱抱*`。清洗后无可发正文时，可配置固定回复，或留空静默。

命中元话术固定回复也可勾选 **只回复一次**，重置时间同样跟回复循环窗口一致。

#### 拆分多条回复

私聊和群聊的“拆分多条回复”开关会把模型回复按自然边界拆成多个微信气泡。显式换行优先；没有换行时，会按句号、问号、感叹号、逗号等边界拆分，并受“最多拆成消息数”限制。

私聊额外支持中文空格停顿拆分：开启私聊拆分后，清洗后的短回复如果只包含中文、中文标点和空格，且空格切出来不超过 3 段、每段都有中文且不超过 20 字，会按空格拆成多个气泡。例如 `傻不傻 我对你什么样，你心里不清楚吗？` 会拆成两条；包含英文、数字、路径或超过 3 段的内容不会按空格拆。

#### 语音回复补充说明

私聊语音回复支持收到语音触发和关键词触发。群聊语音回复只支持关键词触发，并且只影响当前这一轮 AI 回复。语音合成前会使用清洗后的回复文本，避免把 `[语音]` 这类标签读出来；不适合朗读的内容会降级成文字发送。

### 消息指令调用参考

管理员工作台推荐指令：

- `/状态`：查看运行总览。
- `/监听列表`：查看当前监听对象。
- `/自动回复状态`：查看自动回复开关。
- `/当前会话`：查看当前前台模式和已接管好友。
- `/接管 张三`：暂停该好友 AI 自动回复并进入接管。
- `/切到 张三`：切回已接管好友。
- `/结束当前`：退出接管前台，不恢复自动回复。
- `/恢复 张三`：恢复该好友自动回复。
- `/发圈`：进入管理员发圈引导流程。
- `/转发`：进入管理员素材转发引导流程。

`/状态` 按简版运行总览展示：运行时间、当前接口、当前人设、当天累计数据和任务规模。当天累计不受清空任务执行记录影响。当前口径为：

- `API请求`：当天机器人向 AI 大模型和正式 TTS 模型发出的真实请求总数。
- `已收消息`：当天收到的消息条数。
- `已回复消息`：当天成功完成的回复次数，按回复轮次累计，不按拆分气泡数累计。
- `人工接管对话`：当前暂停 AI 回复、由管理员接管的对话数量。
- `定时消息`：当天成功发送的定时消息动作次数，括号内为已启用任务规则数。
- `素材转发`：当天成功素材转发动作次数，括号内为已启用任务规则数。
- `自动转发`：当天成功 AI 自动素材转发动作次数，括号内为当前可用素材数。

停止机器人和更新 `wxautox4` 前的自动停机会等待后台线程真正退出；如果仍在停止中，面板会提示稍后再试。

## 远程访问服务

远程访问服务是 SiverPanel 提供的可选能力，用于把本机管理面板通过固定网址暴露给外部浏览器访问。不开通远程访问不影响本地使用。

使用前请确认：

- 本机面板正在运行。
- 已修改默认账号密码。
- 安全入口没有泄露。
- 远程访问服务激活码与 `wxautox4` 授权不是同一个东西。

连接成功后，通过面板显示的远程地址访问即可；设备离线、面板关闭或网络异常时，远程入口不可用。

## 注意事项

1. 启动机器人时只保留微信主窗口，不要打开多个微信子窗口。
2. 微信主窗口不要最小化。
3. Windows 屏幕缩放建议保持 `100%`。
4. 关闭微信自动更新，避免 wxautox 适配失效。
5. 程序接管微信运行时，尽量不要手动操作微信。
6. 适配环境以当前 wxautox Plus 要求为准。
7. 公开同步代码前，不要提交 `data/config/`、`data/prompt/`、`data/accounts/`、`wxauto_save/`、`wxbot_logs/`、`backups/` 等本地私有数据。

## 常见问题

### Q: 会封号吗？

任何自动化操作都存在风控风险。即使手动操作，频繁群发、异常添加好友、异地登录、低权重账号高频动作，也可能触发平台风控。请只在合法、低频、可控的个人场景使用。

### Q: 跟 wxautox4 什么关系？

本项目基于 wxautox4 做自动化封装。wxautox4 是底层自动化库，本项目是围绕微信自动回复和面板管理做的一层应用。

### Q: 图片识别为什么有时看不到图？

当前图片回复已按结构化图片消息处理。机器人会先尝试生成结构化图片摘要并写入本地记忆；支持视觉的回复接口随后会直接收图，不支持视觉的回复接口会使用这份摘要转述给主回复模型。若仍异常，优先检查图片文件是否可读、识图接口是否可用、接口能力是否已测试。

### Q: 为什么获取不到消息或图片下载失败？

常见原因是微信窗口状态、Windows 屏幕缩放、微信版本或 wxautox 适配问题。先把屏幕缩放调为 `100%`，重启微信和面板，再查看日志。

### Q: 能不能最小化微信？

不能。当前自动化依赖真实微信窗口，主窗口需要保持可见。

### Q: mac、linux 能不能用？

不能。当前只面向 Windows 微信环境。

### Q: 不想调用 AI，能用哪些功能？

可以使用关键词回复、自定义转发、定时消息、随机消息、新好友自动通过和打招呼等不依赖聊天模型的功能。

### Q: 如何更新？

维护源码目录时，直接在当前 worktree 同步最新代码。运行打包目录时，在维护电脑重新执行 `打包发布.ps1`，用新的 `dist/WXBot_Pro.zip` 更新运行目录。更新前建议备份 `data/`。
