# WXBot Pro 使用说明

这份说明面向本地使用者：重点回答“怎么启动、怎么配置、哪里会影响实际回复体验”。代码结构和开发边界请看《WXBot Pro 开发指南》。

## 快速开始

环境要求：

- Windows、Python 3.12、微信 PC 版与 wxautox Plus 环境。
- 微信主窗口保持可见，建议屏幕缩放 `100%`。
- 至少配置一个可用的大模型接口；只测关键词、转发、定时消息时可以先不配 AI。

启动：

```powershell
.\打开软件.bat
```

启动脚本会创建或复用 `venv`、安装依赖并启动面板。面板默认使用 `http://127.0.0.1:10001`，端口占用时会顺延，以启动日志为准。

首次登录面板：

| 项目 | 默认值 |
|------|--------|
| 用户名 | `admin` |
| 密码 | `123456` |

账密保存在 `data/config/admin.json`。开启远程访问前，务必先改默认密码。

## 安装与迁移

维护源码目录时，直接运行 `打开软件.bat`。脚本会自动安装 `Pillow`；缺少 `ffmpeg` / `ffprobe` 时，会下载到 `venv/tools/ffmpeg/`。

需要给另一台电脑一份独立运行包时执行：

```powershell
.\打包发布.ps1
```

产物为 `dist/WXBot_Pro.zip`。它包含运行代码、`data/system_prompts/` 和 `runtime/python/`；首次启动会据此创建新的 `venv/`。本机配置、账号数据、缓存、日志、备份、文档、测试和 Git 元数据不会被打包。

迁移真实使用数据时，优先整目录复制；如果只迁移运行数据，重点保留 `data/`、`wxbot_logs/`、`backups/`。

## 启动后怎么确认能用

1. 登录 Windows 微信，保持主窗口打开。
2. 在面板点击 `启动机器人`。
3. 在状态页确认机器人已运行。
4. 用已监听好友或群聊发消息，验证 AI 回复或关键词规则。
5. 测完后在面板点击 `停止机器人`。

点击停止后，面板会立即显示 `stopping`。已开始的微信动作会收尾；尚未进入微信的可恢复回复会在 15 分钟内按当前规则重新处理，结果未知的动作不会补发。用户主动停止不会自动启动；只有专用 UI 卡死退出码 `86` 才会触发恢复，滚动 30 分钟最多 3 次。

## 模型与 Prompt

### 模型配置

模型配置包括聊天、识图和语音合成接口。默认聊天接口支持主备切换；白名单好友或监听群聊可以绑定专属聊天 / 语音接口，专属配置优先于全局配置。辅助识图在【接口配置】页设置，私聊和群聊各自选择。接口删除前会检查所有绑定关系，仍在使用时需先改绑。

视觉能力需要通过面板测试写入能力记录。支持视觉的回复接口直接收图；不支持时，系统先生成结构化图片摘要，再交给聊天模型回复。

### Prompt 配置

`Prompt` 页面维护基础人设和人设近况：

- 基础人设定义角色、语气和边界。
- 人设近况保存为 `data/prompt/<人设名>-人设近况.md`，用于补充阶段状态。

普通回复和素材文案都会复用这套人设上下文。

聊天模型会看到软件处理时间；微信当前消息附近存在时间条时，还会带入一次大概的“消息时间”。读取不到时直接省略，不影响正常回复。

## 私聊与群聊

### 先看流程图

遇到“为什么这条消息没有立刻回复”“为什么旧回复只发了一半”或“监听窗口为什么正在恢复”时，先用浏览器打开下面两张图，再结合面板日志排查：

- [消息处理流程图](消息处理流程图.html)：说明消息如何去重、排队、路由、生成、发送、取消和恢复。
- [监听维护流程图](监听维护流程图.html)：说明子窗口如何注册和补窗，以及通讯录维护、监听异常和 UI 卡死如何处理。

这两张图描述的是当前运行规则，不是面板操作步骤；日常配置仍以本说明为准。

### 私聊监听

私聊支持白名单模式和黑名单模式：

| 模式 | 说明 |
|------|------|
| 白名单模式 | 只监听列表中的好友，可单独绑定人设、聊天接口和语音接口。 |
| 黑名单模式 | 全局监听未读红点，列表内对象不处理。 |

勾选 `只监听不 AI 回复` 后，私聊仍会记录消息并参与素材转发等流程，但不会触发关键词、轮数超限结束语或聊天模型回复。

全局监听可勾选 `不监听微信免打扰`。黑名单模式会先扫描并保存符合规则的未读，再按需建立子窗口；已取得的消息仍会处理，只有全局扫描真正停止时首页才显示运行异常。

### 群组管理

群聊支持监听、AI 回复、关键词回复、欢迎语、图片识别、语音消息处理和语音关键词回复。

监听群名单中的每个群都可以单独绑定人设、聊天接口和语音接口；选择默认项时跟随全局配置。

`启用群聊监听（仅名单内）` 只监听页面名单中的群；`入群欢迎消息` 开启后，每次识别到新成员入群都会发送欢迎消息，不再提供随机概率。

勾选 `只监听不 AI 回复` 后，群消息仍会被监听、记录并参与关键词回复，但不会调用聊天模型。面板会临时禁用仅被 @ 时回复、回复时 @ 对方等依赖 AI 回复的选项，避免配置冲突。

群聊的 `回复时@对方` 与 `回复时引用` 是两个独立开关。关闭引用后，AI 回复和回复次数超限提示会发送为普通消息；是否 @ 发言人仍按单独开关决定。

关键词回复页的私聊和群聊可分别选择是否 `回复时引用`；群聊还可选择 `回复时@对方`，并可设置 `仅被@时触发`。关闭对应的私聊或群聊关键词回复总开关后，其依赖选项会灰置并暂时不可操作。引用和 @ 可独立组合，只有首条文字会附带相应行为，后续文件继续逐项发送。

私聊和群聊的【内容识别】都可以独立开关 `上下文补洞`；关闭后不补读窗口历史，但实时消息仍正常保存。面板每次打开和之后每 6 小时检查一次软件版本；wxautox4 低于已验证版本 `41.1.1.post1` 时只提示，不自动升级。

## 图片、语音与拆分回复

### 图片识别

私聊图片会进入连续消息合并队列。只发图时，机器人会围绕图片回复；图后补文字时通常合并成同一轮图文消息。单批最多合并 `9` 张图片。

群聊图片默认只缓存，不会因为收到图片立刻调用视觉模型。120 分钟内后续有人明显问图时才会使用缓存图片；A 发图、B 或 C 问图也可以命中，成功回答后仍可继续追问。后续出现新的图片批次时以新批次为主要指代对象；原图缓存过期后，已经成功生成的视觉摘要仍可随常规聊天上下文提供有限兜底。

图片会先保存结构化视觉笔记。发送给 AI 的图片使用 `wxbot_save/compress_images/` 下的压缩副本，原始微信下载文件不会被改动。

### 语音消息与语音回复

语音消息依赖微信自己的语音转文字结果，生产路径不调用 `msg.to_text()`。首次只拿到时长时，系统会短暂等待微信补出正文；最终没有可信正文时静默跳过，不写入 AI 上下文，也不发送失败提示。

面板里的对应开关统一叫 `识别语音消息`。它只决定是否处理微信已经给出的转写结果，不代表机器人内部另有语音识别模型。

私聊和群聊语音回复都可由“收到语音”或关键词触发。群聊选择“群友发语音时”会自动开启语音识别，并且只在“仅被@时回复”关闭时有效，因为微信语音消息本身无法同时 @ 机器人。语音回复限制统一使用“每 N 小时最多 M 条”；任一数字为 `0` 时不限制。语音合成依赖 TTS 配置和 `ffmpeg` / `ffprobe`，合成失败时降级为文字回复。

### 自动拆分回复

拆分回复在本地发送层执行，不要求模型输出特殊标记。显式换行优先；没有换行时，系统会按自然语义边界和最大字数拆分。私聊和群聊各自提供“拆分消息发送延迟”开关：开启时第一条气泡立即发送，第二条及后续气泡之间使用固定的自然停顿；关闭时不增加气泡间隔。

私聊连续消息会等待好友停顿后再回复，默认 `20` 秒，范围 `1 ~ 60` 秒。包含图片时等待更久，方便把后续说明一起带上。每个拆分气泡发送前都会重新检查会话；好友新消息或你从手机手动回复到达后，当前已经开始发送的单个气泡会完成，尚未开始的剩余气泡会取消。

### 回复次数限制

私聊和群聊的“回复行为”中分别提供独立的回复次数限制。私聊按好友统计；群聊按“群聊 + 发言成员”统计，同一成员在不同群互不占用额度，单个成员达到上限也不会影响其他群友。

每次成功完成一轮回复计 `1` 次；一次回复拆成多个气泡仍只计 `1` 次，关键词回复和语音回复也按一轮计数。达到上限后可选择 AI 生成结束语、发送固定回复或静默，并可设置每个滚动窗口只提示一次。任一限制数字为 `0` 时表示不限制。

## 关键词、转发与任务

### 关键词回复

关键词回复支持私聊和群聊，来源依托于 `私聊监听` 和 `群组管理` 的监听对象。一个规则可包含多个关键词别名，支持用 `；`、`,`、中文逗号或换行分隔。回复可以是文案、本地文件，或二者组合；单条规则最多附带 `9` 个文件。

### 素材转发

素材转发用于把微信原生素材主动转发给好友，尽量保留链接、小程序、图片等原生样式。

页面分三块：

- `任务列表`：管理单次任务、循环任务和系统卡片 `AI自动转发`。
- `素材来源`：配置从哪些微信会话收素材。
- 素材来源会按微信实际打开的会话自动识别为文件传输助手、私聊或群聊；无需重复加入私聊或群聊监听名单，且收到的内容仍只用于静默入池。
- `素材管理`：查看素材池、停用 / 恢复素材、维护归属和备注；右上角 `清空素材` 只清除当前所选微信号的素材池，任务配置和转发记录会保留，但固定使用旧素材的任务将无法执行。清空操作不可恢复。

单次任务固定发送一条具体素材；循环任务从筛选范围随机选材。AI 文案会参考基础人设、人设近况、会话记忆、近期聊天、素材内容和转发目标。

`AI自动转发` 只针对有真实新消息的活跃私聊；同一检测窗口内，判定周期和消息门槛都满足时才触发一次判定。每天上限只限制 AI 自动转发，不影响普通素材转发。

### 定时消息与随机消息

定时消息使用 `年月日 + 时间`，内容模型为最多 `1` 条文案和最多 `9` 个本地文件，发送顺序固定为先文案、后文件。

随机消息用于在时间窗口内随机发送普通文本或本地文件，当前只保留一个时间窗口输入。

定时消息按“目标 × 内容”记录执行状态。排队期间如果任务被关闭、删除或修改，旧版本会在进入微信前取消；从通讯录选择的目标会在发送前按联系人身份重新解析当前备注。发送、好友申请、素材转发已经进入微信提交阶段但结果未知时，会标记为 `uncertain` 或待确认，重启后不会自动重发；这是为了避免真实好友收到重复消息。

私聊或群聊在 AI 生成期间意外退出时，机器人重启后会恢复这类明确未答消息。如果首次真实发送已经开始但结果未知，系统会保守冻结，不再自动补发；这可能少回复一次，但不会因为恢复机制重复打扰。

## 通讯录、新好友与关系扫描

### 新好友

新好友页支持自动通过、自动修改备注和标签、新好友自动回复。微信标签必须是当前微信里已经存在的标签。

自动修改备注时始终保留好友原始昵称，面板不再提供关闭昵称的开关。纯表情、少数语言和普通符号昵称都视为有效昵称；只清理控制字符、Unicode 损坏替换符和整串问号等明确不可用内容。无法得到可用昵称时使用带时间的“新好友”名称；备注超长时优先保留昵称，前后缀和时间戳让位。

### 通讯录维护

通讯录页把联系人保存到 `data/accounts/<wx_id>/contact_profiles/contacts.json`。档案只保存联系人真源资料；页面展示名和实际发送目标由系统实时计算，不单独写回档案。

常用入口：

- `立即建档`：通过微信通讯录界面读取完整资料；采集始终在最小子进程完成。
- `停止建档`：停止后续建档，当前批次会先完成。
- `备注修复`：先弹出预览，只处理没有备注且命中规则的联系人。
- `手动校准`：手动选择旧名字并输入新备注 / 昵称，合并聊天记录、会话记忆、关系扫描记录和相关配置。

自动维护固定每批 50 人、完整轮间隔 7 天，采集子进程有 300 秒硬超时。采集期间聊天和微信 UI 会排队，结束后按顺序继续；系统会用微信号或资料指纹复核身份，无法确认时不会猜测发送对象或推进进度。

备注修复、立即关系扫描和手动执行一次好友申请都会先返回“已开始 / 正在执行”，真实微信操作在后台排队；浏览器请求不会等待微信几十秒。

立即建档、停止 / 恢复建档、备注修复和手动执行好友申请始终作用于当前运行机器人实际绑定的微信号。页面此前若停留在历史账号，操作成功后会切回运行账号；立即建档不会把历史账号的续建游标带到当前微信，而是从通讯录顶部开始。好友申请的当前表单设置会与“执行一次”在同一请求中保存到运行账号，保存失败时不会继续提交申请。查看或清理历史档案、关系记录和好友申请记录仍以页面选中的微信号为准。

### 关系扫描

关系扫描用于判断联系人是否疑似删除或拉黑。`立即扫描` 和 `全量扫描` 始终作用于当前运行机器人实际绑定的微信号，不受页面此前浏览的历史账号影响；面板检测到运行账号变化时只自动切换一次，之后仍可手动查看历史账号。后台自动扫描只读取当前会话列表，是短操作；用户点击的全量扫描会先回到顶部，然后作为一次连续、不可抢占的 UI owner 独占任务一直扫到自然结束。扫描中不插入回复，也不提供停止按钮。连续 8 次无新增视为到达末尾；1000 次滚动只是防无限循环的保险，命中时标记为部分完成。扫描结果保存在 `data/accounts/<wx_id>/relationship_scan/relationships.json`。

开启“同步到微信标签”后，机器人会把每个待同步联系人作为一项独立任务排队，每次只修改 1 人；“标签同步间隔”可设置为 1–100 秒，默认 30 秒，失败联系人 10 分钟后再试。聊天不会等待一整批联系人，最坏只会延迟到当前这一个资料修改完成。

主动好友申请中的“最多两次尝试”只用于提交前重新切换会话、核对目标和寻找验证入口。真正调用微信提交后只执行一次；结果未知会标记 `uncertain` 并冻结，禁止自动再次申请。微信会话搜索无法用内部 `contact_key` 区分同名对象，因此发送名称重复或只有纯表情、纯符号等不可搜索名称的联系人不会进入自动申请候选，需要人工处理。

## 记忆管理

记忆分两层：

- 聊天记录：保存原始对话上下文。
- 会话记忆：结构化长期记忆，以 JSON 作为唯一真源。

`带入最近聊天` 只配置一个数字：`最近 N 条`，范围 `1 ~ 200`，默认 `50`。系统会按真实聊天顺序带入最近可见消息，不区分好友、群成员或机器人回复。

私聊和群聊的 `上下文补洞` 分别位于各自监听页的【内容识别】卡片中，两者互不影响。它们与 `带入最近聊天` 也相互独立，后者只决定 AI 回复时是否引用已有聊天记录。

保存聊天历史且开启对应的上下文补洞时，程序会在启动后或监听窗口恢复后的首次 AI 回复前读取一次当前可见窗口，不会周期读取或滚动深历史。补入内容立即参与本轮回复；刚清空聊天记录时不会把旧气泡重新补回。

聊天记录始终按微信原始气泡逐条保存。连续私聊等待期间生成的合并文本只是本轮 AI 输入，不会另外写成一条聊天记录；微信原生合并转发是一个微信气泡，目前只保存外层卡片可读到的预览文字，不会尝试点击展开内部内容。

会话记忆页会同时显示已有会话记忆的对象，以及只有聊天记录、还没有会话记忆的对象。手动提取会先弹出预览，确认后才保存；单次最多分析最近 `500` 条聊天记录。

## 其他配置

- 语音合成接口：支持 TTS 配置、音色和试听；试听缓存落到 `data/cache/tts_preview/`，正式语音缓存落到 `data/cache/tts/`。
- 自动清理缓存：控制 `wxbot_save/` 保留时长，可选 `不清理 / 7天 / 30天 / 90天 / 180天 / 360天`，默认 `30天`。只清缓存，不删聊天记录、会话记忆、配置或账号数据。
- 接口调用失败固定回复：AI / 模型接口失败时可发送固定回复；留空则静默。
- 回复预处理：发送前清洗模型思考标签、内部字段、时间戳和明显 AI 元话术；超长或命中内部字段时会尝试重写一次。
- 报错邮箱：配置保存在 `data/config/email.json`，保存后立即生效。
- 数据图表：`按天` 展示最近 15 天，`按小时` 展示最近 2 天，每 3 小时合并为一个节点并显示对应时间；日期每天只显示一次，具体数据可悬停查看。
- 数据备份：面板可把整个 `data/` 备份到 `backups/data_时间戳/`。

## 日志与排查

面板使用“全部 / 信息 / 成功 / 警告 / 错误”五个筛选项。查看日常收发流水优先看“信息”，查看维护、运营和系统关键成果优先看“成功”；排查问题优先看“警告”和“错误”。面板中的单条日志最多显示 100 个字符，超出部分用省略号截断；本地 `wxbot_logs/log_*.txt` 保留完整内容，并额外保留面板不显示的 `DEBUG` 技术细节。自动测试日志单独保存在 `wxbot_logs/tests/`。

黑名单模式的全局扫描在没有新消息时只进入空闲等待，不会写面板或运行日志。只有扫描到实际消息、但其会话类型不受支持时，才会记录“已跳过不支持的会话类型”。

| 等级 | 含义 |
|------|------|
| `INFO` | 正常业务流水，例如收到消息、实际回复内容、关键词回复、单个目标转发、单人备注修复、排队和自动恢复。 |
| `SUCCESS` | 完整维护或运营任务、关键系统节点明确完成，例如通讯录维护批次、整项素材转发和启动就绪。 |
| `WARNING` | 局部失败、部分完成或结果不确定，但机器人还能继续运行。 |
| `ERROR` | 微信监听器、核心线程或初始化等核心能力受损，需要重启、重建或重新初始化。 |

文字、语音和引用回复只记录已经确认发送成功的内容；语音显示为 `[语音]正文`，多气泡回复用 `｜` 分隔。生成后被新消息取消、尚在排队或发送结果未知的内容不会记成已回复。

多行错误在面板只显示摘要，完整异常与堆栈请查看当天的本地日志文件。

常见排查顺序：

1. 微信主窗口是否可见，是否只保留必要窗口。
2. Windows 屏幕缩放是否为 `100%`。
3. 微信版本和 wxautox Plus 是否适配。
4. 面板日志是否有 `WARNING` / `ERROR`。
5. 模型接口、识图接口或 TTS 接口是否能在面板测试通过。

完整的 2 小时生产验收属于维护验证，命令和通过条件见《WXBot Pro 开发指南》。日常使用不需要运行它。

## 远程访问

远程访问服务是 SiverPanel 提供的可选能力，用于把本机管理面板通过固定网址暴露给外部浏览器。不使用远程访问不影响本地使用。

使用前请确认：

- 面板正在运行。
- 已修改默认账号密码。
- 安全入口没有泄露。
- 远程访问服务激活码与 `wxautox4` 授权不是同一个东西。

## 注意事项

- 自动化操作存在微信风控风险，请只在合法、低频、可控的个人场景使用。
- 不要最小化微信主窗口，尽量避免程序运行时手动操作微信。
- 公开同步代码前，不要提交 `data/config/`、`data/prompt/`、`data/accounts/`、`wxbot_save/`、`wxbot_logs/`、`backups/` 等本地私有数据。
- 代码更新后需要重启面板进程，正在运行的 `web_server.py` 不会热加载本地文件改动。
