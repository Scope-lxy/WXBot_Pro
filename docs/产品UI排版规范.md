# 产品 UI 排版规范

本文档只保留后续 UI 调整时必须遵守的核心规则，不写页面私有结构，不写业务文案约定。

## 核心规范

1. 先看作用域，再看样式。提示、按钮、状态，只能挂在和它直接相关的区块里，不要为了显眼跨整页铺开。
2. 先定层级，再定结构。全站只认 `L1 页面头`、`L2 区块头`、`L3 内容项` 三层；同层级的字号、字重、分割线和留白必须一致。
3. 全站只用固定间距档位：`8 / 10 / 12 / 14 / 16`。不要临时发明页面私有数值。
4. 同级内容共用同一节奏。不要在同一区域里混用两套上下留白，也不要一部分靠 `margin`、一部分靠 `padding` 碰运气对齐。
5. 同类组件只能有一套视觉语言。胶囊、segmented、switch 行、空状态、警告条，在不同页面里也应保持同一套样式和对齐逻辑。
6. 列表优先单行，但不允许硬挤。宽度不足时，顺序必须是：先裁切文本，再自动换行，最后才改单列。
7. 伸缩规则固定。名称类字段可以伸缩；配置类字段保持紧凑固定宽度；删除、开关、短数值一律固定，不参与抢空间。
8. 对齐优先靠容器节奏解决，不靠页面补丁。发现某页不齐，先查层级、间距、组件规则，而不是先写局部修正。
9. 信息层级优先于解释文案。能靠位置、层级、分组表达清楚的，不要再加长说明文案。
10. 左右分栏只允许固定比例，不为单页单独发明新宽度。

## 层级结构

### L1 页面头

- 结构固定为：`图标丨标题丨说明丨弹性空间丨右侧控件`
- 说明固定在标题右侧，不下沉到标题下方。
- 说明默认单行，宽度不足时先裁切，不允许把整行随意撑高。
- 右侧控件可为开关、按钮组、状态胶囊；始终垂直居中，且不参与抢占标题空间。
- `L1` 用于页面级功能头、一级卡片头，不要拿去做列表项或表单小块标题。

### L2 区块头

- 结构固定为：左侧主块 + 右侧控件。
- 左侧主块固定为两行：
  - 第一行：`标题`
  - 第二行：`说明`
- 右侧结构固定为：`弹性空间丨右侧控件`
- `L2` 默认不带图标；只有确实需要强化识别时才允许加图标。
- 当没有右侧控件时，仍保持 `标题在上、说明在下` 的主块结构，不把说明挪回标题右侧。
- `L2` 用于卡片内二级区块，例如“具体规则”“触发范围”“规则详情”。
- `L2` 卡片壳层统一使用：
  - 卡片内边距：`12`
  - 标题下分割线：`1px`
  - 分割线到正文首块：`12`

### L3 内容项

`L3` 不强行统一成一种结构，只允许以下三种子类型：

- `L3-row`
  - 结构：`左侧主信息丨弹性空间丨右侧辅助信息 / 控件`
  - 用于开关行、参数行、单行配置项
- `L3-block`
  - 结构：`小标题` 在上，`内容区` 在下
  - 用于关键词列表、来源列表、目标列表、说明后接输入区的小块
- `L3-item-head`
  - 结构：`标题 / 状态丨弹性空间丨操作`
  - 下方再接元信息或正文
  - 用于规则卡片、任务卡片、素材卡片头部
- 只要 `L3` 被做成“独立白底小卡片”，卡片壳层统一使用：
  - 卡片内边距：`12`
  - 头部到正文：`12`
  - 不允许同类小卡片再混用 `10` 或 `14`

## 说明文案规则

- 说明文案一律使用全局次级文本样式，不单独发明颜色和字体。
- 只有标题允许加粗；说明保持常规字重。
- 需要提示块时，只允许“标题加粗 + 普通说明正文”这一种做法，不再做页面私有的彩色说明块。
- 能靠层级、位置、分组表达清楚的，不额外追加长说明。

## 空状态与等待态

- 列表为空、规则为空、任务为空、素材为空，一律使用同一套线框空状态卡片，不再混用纯文字版和多套私有占位样式。
- 空状态高度默认与标准输入控件同档，使用统一控件高度和统一内边距；内容允许自然增高，但不要先天做成“大块空白框”。
- 对于异步生成类场景，优先使用单一等待态，不额外发明“失败态卡片”或复杂状态矩阵。
- 具体到当前发朋友圈候选文案：
  - 添加任务先入列表，再异步生成候选
  - 生成中统一显示 `正在生成文案...`，并允许通过循环点表现仍在等待
  - 如果生成没有结果，界面继续保持等待态，用户通过 `重新生成` 主动重试
- 等待态文案应出现在内容原本要出现的位置，不要额外弹窗打断主流程。
- 对于“本来应该有数据，但加载请求失败”的场景，优先在当前区块顶部或列表旁边给出就地反馈，不要直接退化成“空状态”，避免把失败伪装成没有数据。

## 间距规则

- 固定档位语义如下：
  - `8`：标题与说明的紧邻关系
  - `10`：同一行内图标、标题、控件之间的标准间距
  - `12`：同组内容块之间的标准间距
  - `14`：较密集卡片内部的补充间距
  - `16`：头部下分割线到正文首块的标准间距
- 禁止继续使用 `4 / 6` 这类页面私有补丁值。
- 同一区域内，只允许一套“分割线到首块”的节奏；不要同页混用 `12` 和 `16`。
- 顶部状态胶囊条单独固定：
  - 上分割线到胶囊：`12`
  - 胶囊到底部分割线：`12`
  - 胶囊条底部分割线到下方首块：`16`
  - 不允许再用“上 12 / 下 16”这类把条内留白和条后留白混在一起的写法。

## 左右分栏比例

- 左右分栏只保留两套：
  - `Split-E`：`50:50`
  - `Split-A`：`60:40`
- `Split-E` 用于左右同级、信息权重相当的双栏页面。
- `Split-A` 用于“主工作区 + 辅助详情 / 参数区”，默认是左主右辅。
- 原则上不使用镜像；只有明确“右侧才是主区”时，才允许把 `Split-A` 反向为 `40:60`。
- 不允许继续新增 `58:42 / 62:38 / 55:45` 这类中间比例，它们都必须归并到 `50:50` 或 `60:40`。
- 移动端一律塌成 `1fr`，不保留双栏比例。

## 换行与伸缩规则

- `L1` 优先保持单行；宽度不足时，顺序必须是：先裁切说明，再让右侧控件换行。
- `L2` 左侧主块允许自然两行；右侧控件不足时整组落到下一行，不把说明重新塞回标题右侧。
- `L3-row` 先保证主标题完整，再处理右侧辅助说明；右侧说明必要时可换行或弱化。
- 删除按钮、开关、短数字、状态胶囊都属于固定宽度元素，不参与抢占主信息空间。

## 使用方式

后续改 UI 时，不先问“这个页面怎么摆更顺眼”，只问四件事：

- 它属于哪一层？
- 它属于 `L3` 的哪一种子类型？
- 它用的是哪一档间距？
- 它是不是复用了同类组件？
- 宽度不够时，是不是先裁切、再换行，而不是硬挤？
