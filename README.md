# WXBot Pro 自用增强版

这是一个面向微信自动回复场景的 WXBot Pro 自用维护版本，基于上游 `SiverWXBot Plus` 持续维护。它保留原项目的私聊、群聊、Prompt、记忆、转发和管理面板能力，并针对人设陪伴、多接口配置、图片识别、会话记忆和回复体验做了定制增强。

当前维护口径很明确：这是个人开发、个人使用的 fork。开发、修复和重构时默认优先当前实际使用体验与代码整洁，通常不为旧任务、旧实例、旧记录额外保留兼容层。

## 文档怎么读

- `README.md`：给使用者看的功能总览、目录说明、使用方式和配置/打包边界。
- `本地项目开发指南.md`：给开发维护者看的当前代码结构、运行链路、数据真源和验证方式。
- `docs/docs.md`：给需要导出或对外同步完整使用说明时用，内容和当前面板行为保持一致。
- `人设编写规范模板.md`：给维护者写人设时用的临时参考模板；它放在根目录，后续可按需要删除或替换。
- `AGENTS.md`：给 AI 协作时用，约束项目边界、风险点和推荐检查命令。

## 适合谁使用

- 想通过 Web 面板维护微信自动回复机器人。
- 需要给不同好友或群聊配置不同 Prompt、模型接口和回复规则。
- 需要私聊图片识别、语音转文字、自动拆分回复、会话记忆等能力。
- 能接受这是个人维护 fork，不保证和原作者仓库持续兼容。

## 运行环境

- Windows
- Python 3.12（`打开软件.bat` 会优先创建 3.12 虚拟环境；自用发布包会内置 3.12 runtime）
- 微信 PC 版与 wxautox Plus 环境
- 可用的大模型接口配置

## 快速启动

```powershell
.\打开软件.bat
```

`打开软件.bat` 会自动创建 `venv`、安装依赖，并启动管理面板。开发时也可以手动运行 `venv\Scripts\python.exe web_server.py`。
启动后打开管理面板，按页面提示配置模型接口、监听对象、基础人设 Prompt 和相关开关。

如果当前机器的系统环境里没有 `ffmpeg` / `ffprobe`，`打开软件.bat` 还会在首次启动时自动从 `BtbN/FFmpeg-Builds` 下载 Windows 预编译包，并解到项目自己的 `venv\tools\ffmpeg\`。如果系统里已经有可用的 `ffmpeg` / `ffprobe`，则会直接复用，不重复下载。
面板默认优先占用 `http://127.0.0.1:10001`；如果该端口已被占用，会顺延到后续空闲端口。

## 当前软件怎么跑起来

当前启动链路是：

```text
打开软件.bat
-> web_server.py（Flask 面板、配置保存、备份、接口测试、管理 API）
-> /start_bot
-> 后台线程创建 WXBot
-> wxbot_core.py 主循环
-> 微信监听 / AI 回复 / 统一时间任务扫描 / 聊天时智能转发待发送队列 / 通讯录自动维护
```

这意味着现在的真实运行入口分成两层：

- 面板层在 `web_server.py`，负责登录、读写配置、管理页 API、备份、Prompt/记忆/通讯录/发圈等页面动作。
- 机器人运行层以 `wxbot_core.py` 为主编排，负责 wxautox4、统一时间任务、素材转发、接管和微信真实发送动作；监听维护、消息路由、通讯录维护等业务规则已拆到 `feature/` 模块。

## 重要目录

- `data/config/config.json`：本地配置文件，包含模型接口、开关、监听列表等。
- `data/config/email.json`：报错邮件 / 离线提醒 SMTP 配置。
- `data/config/webhook.json`：Webhook 通知配置。
- `data/config/reply_count.json`：私聊回复轮数限制的运行时计数，当前按好友分别记录。
- `data/accounts/<wx_id>/contact_profiles/`：本地通讯录档案目录，保存 `contacts.json` 与维护元数据。
- `data/accounts/<wx_id>/tasks/material_outreach/`：素材转发任务、素材池、运行态与执行记录。
- `data/prompt/`：基础人设 Prompt 目录，同目录下也会保存每个人设的可选近况文件，命名形如 `<人设名>-人设近况.md`；目录里也可以放可直接复制的人设模板，例如当前的 `模板.md` 和 `模板-人设近况.md`。
- `data/system_prompts/`：系统级 Prompt 片段，例如拆分回复规则、微信正文格式约束、图片视觉上下文协议、会话记忆规则；同目录下的 `prompt_backup/` 统一保存这些片段的 `.md` 恢复文件。
- `data/accounts/<wx_id>/memory/`：聊天记录与近期上下文。
- `data/accounts/<wx_id>/conversation_memory/`：会话记忆 JSON 文件。
- `data/accounts/<wx_id>/moments_drafts/`：管理员发圈草稿运行态。
- `data/accounts/default/`：只有在当前没有运行中微信号、没有 `last_wx_id`、也没有任何已有账号数据时，才会使用的默认账号空间。
- `panel_logs/`：面板运行日志，位于软件根目录，不属于 `data/` 用户数据。
- `backups/`：软件根目录下的数据备份目录，备份结构为 `backups/data_时间戳/`。
- `core/`：机器人底座能力，例如配置校验、媒体识别、Prompt、记忆、发送和调度规则。
- `feature/`：机器人业务功能，例如监听维护、消息路由、自定义转发、新好友、定时消息、朋友圈任务。
- `extension/`：外部扩展能力，例如邮件通知、Webhook、SiverPanel 远程访问。
- `templates/dashboard.html`：Web 管理面板。
- `wxbot_core.py`：机器人运行主编排。

## 当前增强点

这份 fork 的增强点按能力分组维护，避免把 README 写成变更流水账：

- AI 回复：私聊 / 群聊支持只监听不回复、图片直传或两段式识图、语音转文字、语音回复、本地拆分回复、发送前清洗、接口失败固定回复和默认聊天接口主备切换；私聊拆分开启时，纯中文短回复里的空格停顿可自动拆成多个气泡。私聊勾选 `只监听不 AI 回复` 后，会直接跳过关键词回复、轮数超限结束语和普通 AI 回复；自定义转发除外。
- Prompt 与人设：需要人格上下文的链路统一由 `PromptSystem` 组装，基础人设、人设近况、会话记忆、当前时间和会话名不再在多个文件里手工拼装；技术协议型 Prompt 继续独立维护。
- 账号与数据：账号选择按 `运行中微信号 -> last_wx_id -> 有实际文件内容的历史账号 -> default` 解析；空账号壳层不再算有效账号，失效 `wx_id` 会要求重新选择。
- 管理员工作台：管理员窗口只做运行控制台，支持状态查看、监听管理、发圈、素材转发和人工接管；空闲、接管、发圈、转发四种前台模式互斥。
- 通讯录与新好友：通讯录支持手动建档、暴力建档、自动维护、备注修复和三栏查看；新好友可自动备注并同步已有微信标签；好友申请方案已按“来源 -> 候选人 -> 文案规则 -> 发送器”的可扩展模型整理，首期用于从 `删除我的人` 等标签来源发起好友申请。
- 任务工作台：`关键词回复`、`自定义转发`、`定时消息`、`素材转发`、`发朋友圈` 这 5 个双栏页面复用同一套工作台外壳，桌面端左侧列表独立滚动，右侧详情保持同屏。
- 素材转发：页面分为 `任务列表 / 素材来源 / 素材管理`。素材任务支持单次任务、循环任务、附加文案和 AI 自动转发；普通任务与 `AI自动转发` 共用“统一文案”生成层，会参考基础人设、人设近况、会话记忆、近期聊天和素材内容。
- AI 自动转发：只针对有真实新消息的活跃私聊，按 `判定周期（分钟）` 和 `判定门槛（条消息）` 触发；`每天最多转发（次）` 只限制单个好友当天成功发送次数，不影响普通单次 / 循环素材转发。
- 统一时间任务：定时消息、素材转发、发朋友圈任务和朋友圈点赞共用统一调度模型；保存配置后，运行中的后续任务会热同步，已经开始的一轮会先执行完。
- 会话记忆：会话记忆以 JSON 为唯一真源，AI 只返回提案 JSON，由程序合并、校验、排序和保存；手动提取会先预览，后台维护只处理新增聊天记录。
- 媒体上下文：AI 可见历史统一走媒体净化，图片 / 视频 / 文件不再把本地绝对路径直接喂给模型，媒体上下文最多保留最近 `3` 条。
- 运行体验：停止机器人和更新 `wxautox4` 前的自动停机会等待后台线程真正退出；报错邮箱配置保存在 `data/config/email.json`，面板保存后立即生效。

## 管理员工作台

当前管理员窗口已经从“命令版后台”收缩成运行控制台，主要负责：

- 查看机器人当前运行状态
- 管理监听名单和关键运行功能
- 发圈
- 创建素材转发任务
- 临时接管好友并进入接管前台

当前工作模式有四种：

- `空闲`：普通消息会收到明确提示，不再静默吞掉
- `接管`：管理员普通文本和图片会自动回给当前接管好友
- `发圈`：普通文字和图片会继续追加到发圈草稿
- `转发`：管理员按提示逐步创建一条素材转发任务

常用管理员指令：

- `/帮助`
- `/状态`
- `/监听列表`
- `/自动回复状态`
- `/当前会话`
- `/接管 张三`
- `/恢复 张三`
- `/切到 张三`
- `/结束当前`
- `/人设列表`
- `/切换人设 小东-知己版`
- `/发圈`
- `/重新生成`
- `/取消发圈`
- `/转发`
- `/取消转发`

`/状态` 里的“数据统计”现在统一按当天累计展示，且不再受清空任务执行记录影响。当前口径如下：

- `已收消息`：当天收到的消息条数。
- `已回复消息`：当天成功完成的回复次数，按回复轮次记 `1`，不按拆分出的气泡数累计。
- `定时消息`：当天成功发送的定时消息动作次数；发给多人、多条内容时按实际成功发送动作累计。
- `素材转发`：当天成功素材转发动作次数；发给多人、多次时按实际成功动作累计。
- `AI转发次数`：当天成功 AI 自动素材转发动作次数。
- `发朋友圈`：当天成功发布朋友圈次数。

发圈链路当前行为：

- `/发圈` 后会提示“请现在发送文案或图片给我，20秒内未收到会自动取消；收到后我会自动生成 3 条 AI 文案”
- 进入发圈后，20 秒内完全没收到内容会自动取消
- 开始收集内容后，如果最后一次新内容之后 20 秒内没有继续输入，会自动生成 3 条 AI 文案
- 生成候选后先回复 `1 / 2 / 3` 选择文案，再回复 `1` 确认创建任务，或回复 `0` 取消

接管链路当前行为：

- `/接管 XXX` 会暂停该好友 AI 自动回复，并把管理员窗口切到该好友的接管前台
- 被接管好友的新消息会同步到管理员窗口
- 管理员窗口中的普通文本和图片会自动回给当前接管好友
- 如果当前正在发圈，新接管消息会挂到后台待处理，不会污染发圈草稿
- `/切到 XXX` 或再次 `/接管 XXX` 时，会先把这个好友积压的待处理文本/图片逐条补发给管理员，再清空 pending
- `/结束当前` 只退出当前前台接管，不恢复自动回复
- `/恢复 XXX` 才会真正恢复该好友自动回复
- 当前接管链路已支持文本和图片；文件接管暂不支持

素材转发管理员链路当前行为：

- `/转发` 后会提示“请现在转发一条素材给我，20秒内未收到会自动取消”
- 20 秒内没有收到可转发素材会自动取消
- 收到素材后，会读取当前运行微信号的通讯录标签，只展示前 9 个常用标签
- `想发给谁` 里回复 `1` 表示全部，再进入 `不发给谁`
- `想发给谁` 里回复 `23`、`2 3` 或 `2,3` 表示只发给第 2 和第 3 个标签
- `你想什么时候开始发送` 里回复 `1 / 2 / 3` 表示 `10 / 30 / 60` 分钟后；回复其他正整数则表示 `X` 分钟后
- 最后只创建 1 条单次转发任务；确认回复 `1`，取消回复 `0`

## 通讯录与素材转发

### 通讯录维护

通讯录页当前用于读取微信联系人信息并保存到本地，不承担真实发送。

- 手动入口：`立即建档`、`暴力建档`、`停止建档`、`备注修复`
- `立即建档`：标准模式，默认每批读取 `10` 个联系人，最多连续读取 `50` 个；每批开始前会自动把微信切到前台通讯录，但不会持续抢焦点，方便切回面板手动停止
- `暴力建档`：默认每批读取 `20` 个联系人，会持续读取到完成或用户手动停止，更容易触发微信风控
- 自动维护：可配置是否开启、`维护完后间隔`、`每批维护人数` 和 `每批维护间隔`；每次只跑单批，批次开始前会自动把微信切到前台通讯录，不做持续置顶锁
- 浏览方式：三栏只读查看器，按 `微信号 -> 标签 -> 联系人列表` 浏览
- 状态面板：最后更新、联系人总数、重复联系人、待修复备注；建档反馈会区分“本轮读取条目数”“本轮新增唯一联系人”“当前唯一联系人总数”

建档过程中如果连续出现尾部联系人重复返回、未推进或空批次，程序会自动重试 `3` 次；仍然异常时会停止本轮并提示“疑似卡住”，不再误报“建档完成”。
自动维护不会在刚启动机器人时立刻触发；至少会先等满一个“每批维护间隔”后，才开始第一批。`维护完后间隔` 控制的是“上一轮维护完后，隔多久自动开始下一轮”，不是单批之间的分钟间隔。
同一次连续手动建档会优先沿用微信当前保留的通讯录位置，不会每批都从顶部重找；如果机器人重启或 UI 位置漂移，则会按保存的锚点重新定位后再继续。

备注修复会先弹出预览窗口，按“修复前 -> 修复后”双列展示本次将修复的联系人；已有备注不会被覆盖。修复成功后会立刻回写本地 `contacts.json`，并在运行日志输出开始、逐条修复和汇总结果。
新好友页里的“自动修改备注和标签”也会复用这套通讯录信息：可以给刚通过的好友自动生成备注，并同步一组已经存在于微信里的标签。

好友申请后续作为【新好友】页内的独立 L1 模块规划，首期读取 `删除我的人` 或其他自定义标签作为候选来源；模块设计不绑定单一标签，后续可扩展批量名单、搜索关键词、群成员和名片消息等来源。详细方案见 `docs/friend_request_outreach_plan.md`。

### 素材转发

素材转发现在是独立页面；`随机消息 / 定时消息` 保持在各自页面。保存配置后，如果机器人已经在运行，后续任务会自动按新配置热同步，不用手动重启；当前正在执行的一轮会先完成。

当前页面结构：

- `任务列表`：管理 `单次任务 / 循环任务`，以及系统卡片 `AI自动转发`
- `素材来源`：配置从哪些微信会话收素材，以及每个来源的素材上限
- `素材管理`：查看素材池、停用 / 恢复素材、维护素材归属和备注

任务配置规则：

- `单次任务`：固定发送一条具体素材。`素材来源 / 素材类型` 只作为筛选器，帮助你更快在 `选择素材` 里定位某条素材。
- `循环任务`：从当前筛选范围里随机选材。`素材来源 / 素材类型` 会直接限制本任务允许参与随机的素材范围。
- `附加文案`：支持 `无文案 / 自定义 / AI 文案`；选择 AI 文案时，`转发目的` 是可自定义的单行输入，默认提示包含 `日常问候 / 升温关系 / 引导支持`，`文案力度` 可选 `含蓄委婉 / 自然表达 / 积极主动`，还可再补一段额外要求。
- 任务卡片里的 AI 文案最终都会走统一文案层：会结合基础人设、人设近况、会话记忆、最近聊天和素材信息，生成更贴当前关系的一两句话。
- `发送目标`：支持全部、按标签包含、按标签排除，以及手动输入昵称或备注；手动输入也必须命中当前微信号本地通讯录档案。
- `时间规则`：固定发送直接选 `年月日 + 时间`；循环任务使用单个 `时间窗口`。

素材管理当前支持：

- 查看素材来源、类型、素材归属、转发测试状态、当前是否可转发。
- `停用 / 恢复` 某条素材，控制后续任务和智能转发是否还能继续使用它。
- 修改 `素材归属`（我的作品 / 第三方作品）和 `备注`，用于补充使用场景、版权提醒或转发说明。

AI自动转发当前行为：

- 只针对当前有真实新消息的活跃私聊。
- 系统卡片只保留 `判定周期（分钟）`、`判定门槛（条消息）`、`每天最多转发（次）` 3 个控制项。
- 同一检测窗口内，只有 `判定周期` 和 `判定门槛` 都满足时，才触发 1 次新的 AI 判定。
- 如果消息门槛先达到，就继续等时间到；时间到了以后，即使后面没有继续来新消息，也会补触发这 1 次。
- 新消息按对方任意私聊消息计算，表情也算。
- `每天最多转发（次）` 只限制 AI 自动转发对单个好友当天成功发送的次数，不影响普通单次 / 循环素材转发。
- 判断命中后会先写入本地待发送队列，再按延迟时间转发素材；当前运行态只维护 `ai_detection_state` 和 `ai_pending_queue`，不再维护补检运行态或 miss 节流状态。

随机消息 / 定时消息当前行为：

- 两者共用同一套任务详情编辑器，内容模型统一为“最多 `1` 条文案 + 最多 `9` 个本地文件”。
- 发送顺序固定为先文案、后文件；图片也按文件处理，普通文件不会再误当成文本发出去。
- 文件路径只保存当前运行电脑可访问的本地绝对路径。

记录与日志说明：

- 右侧 `转发记录` 会显示短时间、素材、状态和简短说明；素材优先显示 `[类型] 标题`，若标题本身已经带有类型前缀则不重复补。
- 素材入池日志同样会显示来源、中文类型和素材标题，不再暴露内部 `mat_xxx` 识别码。
- 任务执行日志会记录任务开始、单目标发送 / 跳过和任务汇总，方便工作机真实验证。

任务工作台补充说明：

- `定时消息`、`素材转发`、`发朋友圈任务` 现在共用统一的右侧 `任务队列与执行记录` 卡片，但不要把它们理解成同一种“手动队列”。
- `定时消息` 和 `素材转发` 的任务卡片负责定义规则；待执行实例由系统按卡片设置自动生成。停用任务后，已生成但尚未执行的实例会直接取消，后续也不再继续生成。
- `素材转发` 右侧显示的是具体待发送实例，例如 AI 聊天智能转发待发送记录、AI 前置文案待生成记录，而不是把整条任务手动塞进去。
- `发朋友圈任务` 仍然是一条明确的发布动作：先建任务、生成候选、确认或取消；只有确认后的任务才会进入待执行区。
- 工作台标题现在统一按“内容优先”显示，不再使用“定时发圈 / 固定发送 / 随机发送”这类时间型壳标题。
- `定时消息` 的任务卡片、待执行实例和执行记录会直接显示首条文案；如果这条任务只有文件没有文案，就回退显示首个文件名。
- `素材转发` 的单次任务标题直接使用素材 `content_preview`；循环任务标题使用 `素材来源 + 素材类型`。待执行实例和执行记录统一显示实际命中的那条素材 `content_preview`。
- `发朋友圈任务` 的任务卡片标题直接显示当前最终会发出去的文案：AI 文案模式显示选中的文案，原始文案模式显示原始文案；没有文案时显示 `无文案`。
- 工作台卡片现在统一成三行：第一行标题，第二行辅助摘要，第三行时间、发送目标和范围信息。任务大卡片与底部 `运行时实例 / 执行记录` 都遵循同一套层级。
- 第二行只放模块自己的补充信息：`定时消息` 显示附件文件名 / 文件数量，没有附件显示 `无附件`；`发朋友圈任务` 显示图片文件名 / 图片数量，没有图片显示 `无图片`；`素材转发` 显示实际附加文案或 AI 文案生成方式，没有文案显示 `无文案`。不要再把来源、素材类型、目标或结果统计塞进第二行。
- 第三行固定先显示时间，再显示发送目标、标签、可见范围等执行维度；只有失败或需要补充说明时，才在后面继续拼失败原因或失败次数，不再把“发送了几次动作”这类工程统计直接暴露给用户。
- `发朋友圈任务` 的执行记录成功时不会再重复显示 `发布成功`；失败时才会在第三行补失败原因。`素材转发` 的执行记录第二行只显示实际发出去的附加文案，没有文案就显示 `无文案`。`定时消息` 的执行记录第三行会显示 `发给：...`，有失败时再补 `失败 N 次`。
- 这次没有新增新的工作台历史文件；`定时消息`、`素材转发`、`发朋友圈任务` 仍然只复用各模块原来的 `runtime.json / history.json`。
- `定时消息` 会把本轮目标和消息快照写回现有运行态 / 执行记录，用来支撑工作台摘要。
- `发朋友圈任务` 会把实际发布文案和图片快照写回现有运行态 / 执行记录，工作台里看到的是最终真实发布内容，不是旧候选壳。
- `素材转发` 会把批次上下文保存在现有运行态 / 执行记录里，并按 `batch_id / run_id` 聚合展示；AI 前置文案、待发送实例和实际转发结果都共用这一套口径。

## 自定义转发与管理员处理

当前自定义转发分成两类：

- 普通转发通知：按你填写的转发目标转发，不影响关键词回复和普通 AI 回复
- `命中后转发给管理员处理`：命中后暂停该好友 AI 自动回复，并把消息转给管理员窗口

当勾选 `命中后转发给管理员处理` 时：

- 面板会自动隐藏 `转发目标` 和 `转发时附带来源信息`
- 处理目标固定为管理员窗口
- 系统会强制附带来源窗口和发送人信息
- 该规则优先级高于关键词回复；命中后，本条消息不会再继续触发关键词回复或普通 AI 回复
- 如果管理员窗口当前在发圈，接管消息会挂到后台待处理，等退出发圈后再继续处理

如果处理目标就是管理员窗口，还会自动建立接管会话，管理员可以直接接管处理或后续手动恢复自动回复。

## 其他配置补充

### 备用接口设置

当前面板支持给聊天主接口配置一个备用聊天接口，用于主接口连续报错时自动接管：

- 只影响聊天接口，不影响识图接口
- 失败阈值默认 `3` 次，指的是**当前运行中的连续失败次数**
- 只要主接口成功一次，失败计数就会清零
- 切到备用接口后，程序会按固定间隔自动探测主接口；探测成功后会自动切回主接口
- 重启机器人或保存 API 相关配置后，也会回到主接口并重新开始计数

如果某个白名单私聊好友或监听群聊被单独绑定到了专属聊天接口，仍优先走它自己的绑定，不参与默认聊天接口这套主备切换。

### 启用发送延迟

当前面板会同时暴露：

- 首条回复最小延迟
- 首条回复最大延迟
- 拆分消息发送延迟（较快 / 标准 / 较慢）

其中拆分消息发送延迟只影响拆分后的后续消息：

- `较快`：最快一档节奏
- `标准`：当前的 `2 倍`
- `较慢`：当前的 `4 倍`

### 超出次数限制固定回复

当前私聊回复轮数限制按好友分别计数。某个好友在当前计数周期内超过回复轮数上限时，可按以下方式收尾：

- `AI自动生成`：默认开启。会使用 `data/system_prompts/closing_reply.md` 配合当前人设、人设近况、会话记忆和最近聊天上下文，生成一句简短、自然的结束语。
- 手动固定回复：关闭 `AI自动生成` 后可手动输入一条固定文案。
- 静默不回复：关闭 `AI自动生成` 且输入框留空。

`只回复一次` 同时作用于 AI 自动生成和手动固定回复。轮数计数保存在 `data/config/reply_count.json`，当前按好友分别记录，机器人重启后不会丢失。

如果超限结束语的 AI 生成本身又遇到接口报错，会回退到“接口报错回复”配置；该配置留空时保持静默，不会把内部报错占位文案发给用户。

### 其他配置里的管理员设置

管理员设置已移动到【其他配置】页签最下面，继续走页面统一保存，不单独提供卡片内保存按钮。

如果 `文件传输助手` 同时被你用作管理员窗口和素材来源，当前规则是：

- 管理员指令、接管模式、发圈模式优先
- 之后才会考虑素材识别入池
- `不回复素材来源的普通消息` 只影响“非管理员素材来源窗口”的普通消息，不影响管理员工作台

### 发朋友圈里的添加任务与候选生成

当前面板里的 `添加任务` 已经拆成两段：

- 第一步：创建任务。只要弹窗里这一组素材有文案或图片，点下后就会立即进入左侧任务列表；空内容时按钮静默无效，不再弹窗打断。
- 第二步：异步生成 AI 候选。任务创建成功后，面板会在后台请求 3 条候选文案；这段时间右侧详情会持续显示 `正在生成文案...` 的循环等待态，而不是卡住整个弹窗。

这意味着：

- 用户会先看到任务卡片出现，再看到候选文案陆续可用
- 即使 AI 接口较慢，添加动作本身也不会像“卡死”
- 如果候选迟迟没有出来，仍然可以手动点 `重新生成`

当前面板里的发圈可见范围控件已恢复：

- 任务列表上方可单独选择 `全局发圈接口`，只影响发圈文案生成，不会改聊天主接口。
- 选中任务后，可以在 `全部` / `谁可以看` / `不给谁看` 之间切换
- 选择 `谁可以看` 或 `不给谁看` 后，可以按当前微信号通讯录标签搜索并选择可见范围
- 保存任务时会记住当前可见类型和标签，真正发布时会传给朋友圈发布内核

## 配置与数据说明

这个 fork 后续主要按自用场景维护。跨设备继续使用时，建议直接备份并复制：

- `data/`

如果你像现在这样把整个项目目录直接迁到新的实际工作电脑，并且后续就在这台机器上继续开发和运行，那么当前目录本身就可以视为新的主工作目录，不必再额外走一次“打包后再部署到另一台机器”的流程。
如果你是照着旧教程找迁移入口，先确认仓库里是否真的保留了迁移脚本；当前这份 worktree 默认不再附带旧版迁移脚本目录。

当前运行目录只认这些位置：

- `data/config/`：主配置、面板账号、邮箱、Webhook 等
- `data/prompt/`：基础人设和人设近况
- `data/accounts/<wx_id>/`：聊天记录、会话记忆、任务、通讯录、发圈草稿等账号级数据
- `panel_logs/`：面板运行日志

新装默认会创建 `data/config/config.json` 和 `data/prompt/默认.md`。会话记忆和任务规则都以当前目录结构为准，不额外维护平行旧目录。

## 打包提醒

发到工作电脑自用时，标准打包入口是根目录的 `打包发布.ps1`，产物默认输出到 `dist/WXBot_Pro.zip`。这个包会自带本地 Python 3.12 runtime，工作电脑不需要再装 `py` 或 `uv`。

如果当前这台机器既是实际运行机，也是你日常改代码的工作机，那么 `打包发布.ps1` 更适合在“需要给另一份独立运行目录做更新”时使用；日常开发不需要每改一次都先打包。

`打包发布.ps1` 现在只会打包 `core/`、`feature/`、`extension/`、`templates/`、`data/system_prompts/` 和启动所需的根目录文件，不会再把 `data/config/`、`data/prompt/`、`data/accounts/`、`panel_logs/`、`docs/` 打进包里。脚本仍会排除 `backups/`、`dist/`、`tests/`、本地 `venv/`、`.git/` 和临时运行时目录。

这也意味着自动下载到 `venv\tools\ffmpeg\` 的 `ffmpeg` / `ffprobe` 不打包。工作电脑如果缺少它们，会在首次运行 `打开软件.bat` 时按当前项目规则自动补齐。

如果包里没有 `data/config/config.json`，程序仍然可以启动：首次运行时会自动创建默认配置文件。但这样不会带上维护电脑上的监听、接口和人设绑定配置，更适合工作电脑已经有一套在用、只需要更新代码和系统 Prompt 的场景。

同步到公开 GitHub fork 时，仓库规则应尽量只保留代码、公开文档和必要模板，不提交本地私密配置、人设模板、运行日志、会话数据和内部工作文件。

默认不应提交：

- `data/config/*.json`
- `data/prompt/*.md`
- `data/accounts/`
- `panel_logs/`
- `backups/`
- `docs/superpowers/`
- `panel_secret.key`

默认可以保留公开仓库的内容：

- 代码文件与测试
- `data/system_prompts/*.md`
- `data/system_prompts/prompt_backup/*.md`
- 面向公开使用的 README 和 `docs/`

如果某些私密文件此前已经被 Git 跟踪过，单纯修改 `.gitignore` 不会自动把它们移出公开提交范围；后续公开提交前还需要先把这些文件从跟踪列表里移除。

## 常见问题

### 图片识别为什么有时看不到图？

如果“合并连续私聊消息”开启，旧逻辑可能把图片路径当成普通文字传给模型。当前版本已改为按图片消息结构处理：支持视觉的回复接口直接收图；不支持视觉的回复接口会先调用辅助视觉接口，把图片整理成结构化视觉笔记，再交给主回复模型生成最终回复。

### 语音转文字是不是调用大模型？

不是。当前语音转文字主要依赖微信自带的“语音消息自动转成文字”能力。若转文字失败，请在微信设置中开启对应功能。

### PowerShell 里看到中文乱码怎么办？

这通常是 Windows 控制台编码显示问题，不代表源码损坏。开发和排查时请按 UTF-8 读取文件。
