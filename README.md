# WXBot Pro 自用增强版

这是一个面向 Windows 微信自动回复场景的 WXBot Pro 自用维护版本，基于上游 `SiverWXBot Plus` 持续维护。它保留原项目的私聊、群聊、Prompt、记忆、转发和管理面板能力，并围绕人设陪伴、多接口配置、图片识别、会话记忆和回复体验做了定制增强。

这份仓库的维护口径很明确：优先当前实际使用体验与代码整洁，通常不为旧任务、旧实例、旧记录额外保留兼容层。

## 适合谁使用

- 想通过 Web 面板维护微信自动回复机器人。
- 需要给不同好友或群聊配置不同人设、模型接口和回复规则。
- 需要图片识别、语音转文字、自动拆分回复、会话记忆、素材转发等能力。

## 运行环境

- Windows
- Python 3.12
- 微信 PC 版与 wxautox Plus 环境
- 可用的大模型接口配置

## 快速启动

```powershell
.\打开软件.bat
```

启动脚本会自动创建或复用 `venv`、安装依赖并启动管理面板。图片压缩依赖 `Pillow`，脚本会随其他 Python 依赖一起安装，并在复用旧虚拟环境时补检。开发时也可以手动运行 `venv\Scripts\python.exe web_server.py`。

面板按钮依赖的 jQuery 已随项目本地托管，不需要等待外部 CDN 才能启动、停止或保存配置。

如果系统里没有 `ffmpeg` / `ffprobe`，脚本会首次自动下载 Windows 预编译包到 `venv\tools\ffmpeg\`；如果系统 PATH 已经有可用版本，则直接复用。面板默认优先使用 `http://127.0.0.1:10001`，端口被占用时会顺延。生产环境不安装、不初始化也不读取 `wechat-cli`。

## 运行结构

当前真实启动链路是：

```text
打开软件.bat
-> web_server.py
-> /start_bot
-> 后台线程创建 WXBot
-> wxbot_core.py 主循环
```

可以把它简单理解成两层：

- `web_server.py` 负责面板、配置读写、页面 API、备份、接口测试和启动/停止机器人。
- `wxbot_core.py` 负责编排微信监听、AI 回复和运营任务；全部真实微信动作提交给唯一 UI owner，通讯录最小采集子进程是唯一并发例外。

## 重点能力

- AI 回复：支持私聊 / 群聊、图片直传或两段式识图、语音转文字、语音回复、连续消息合并、本地拆分回复、回复预处理、手机手动回复接管，以及默认聊天接口主备切换。
- Prompt 与人设：基础人设、人设近况、会话记忆和时间上下文统一组装，减少多处手工拼 Prompt。
- 管理员工作台：管理员窗口作为运行控制台，支持状态查看、接管、发圈和素材转发；状态面板和 `/状态` 会展示当天收发与 API 请求统计。
- 通讯录与新好友：支持手动建档、自动维护、身份校准、备注修复、关系扫描、好友申请和标签同步；自动维护正常批次固定 50 人、完整轮 7 天，采集子进程 300 秒硬超时。批次从启动到恢复聊天页期间暂停全部聊天处理和微信 UI，消息按到达顺序排队，恢复后再处理。每批先回到通讯录顶部，再用名称定位、稳定身份复核和虚拟重复去重推进安全游标；短批后只用内部 2 人探针确认尾部，证据不足不会误报完整轮完成，完整资料字段不缩水。
- 任务系统：定时消息、素材转发和发朋友圈任务共用统一调度模型，保存配置后可热同步后续任务。排队任务在进入微信前复核最新任务版本和联系人身份；文字、文件、欢迎语和 quote 后续内容逐项提交，停止、配置变化或新消息可取消尚未开始项。调用方等待 owner 给出明确完成或取消结果，固定秒数只用于当前 UI 动作的卡死检测，不会因队列较长而先报失败再晚到执行。语音、文件、转发、quote 等非幂等微信投递使用持久化提交账本；结果不明时标记 `uncertain`，重启不自动重发。
- 会话记忆：以 JSON 为唯一真源；机器人停机期间发生的对方消息和手机人工回复，会在恢复后的首次 AI 回复前从当前可见窗口按微信顺序补进聊天记录并带入 AI 上下文。补洞不滚动深历史，重复文字和相同图片按实际出现次数保留；微信未给出精确时间时，推算时间只用于排列，不能把已存在的旧消息再次补入。
- 素材转发：支持单次任务、循环任务、素材来源管理和 AI 自动转发。
- 监听维护：动态监听现在走轻量按需补窗，不再靠主循环高频巡检或残留窗口强清理来维持。
- 回复恢复：私聊和群聊消息进入 AI 分支后会持久化待答状态；进程在 AI 生成期间退出时，重启后只重新排队这类明确中断的消息。一旦已经开始真实发送但结果未知，则冻结为 `uncertain`，不自动重发。
- 运行体验：停止按钮立即进入 `stopping`，机器人线程自行收尾；只有 UI 卡死专用退出码 `86` 才触发自动恢复，滚动 30 分钟最多 3 次，用户主动停止不会自动启动机器人。

具体页面怎么操作，请看 `docs/WXBot Pro 使用说明.md`。

## 重要目录

- `data/config/`：主配置、面板账号、邮箱、Webhook、回复轮数统计、小时级运行统计等运行配置。
- `data/prompt/`：基础人设和人设近况文件。
- `data/system_prompts/`：系统级 Prompt 片段及其备份。
- `data/accounts/<wx_id>/`：聊天记录、会话记忆、通讯录、任务、发圈草稿等账号级数据；通讯录档案使用 v2 瘦身结构，只保存联系人真源字段，展示名和发送目标由运行时派生。
- `core/`：底座能力，例如配置、Prompt、媒体、发送和调度。
- `feature/`：机器人业务规则，例如监听维护、管理员工作台、素材转发、任务执行。
- `extension/`：邮件通知、Webhook、SiverPanel 远程访问等外部增强。
- `tools/`：本地探针和复现脚本，只放临时、测试性质的辅助工具，不放正式运行文件。
- `templates/`：Web 管理面板模板与静态资源。
- `venv/tools/`：启动脚本维护的项目级外部工具目录，目前正式运行只使用 `ffmpeg/`。
- `wxauto_save/`：微信下载原件和 AI 图片压缩副本缓存；机器人启动时会按面板配置后台清理，默认保留 30 天。
- `wxbot_logs/`：面板运行日志。
- `backups/`：面板一键备份产物，不是运行时账号数据真源。

## 使用与维护边界

- 微信主窗口需要保持可见，不要最小化。
- 这是个人自用 fork，默认优先当前目录结构和当前使用方式，不额外维护旧版迁移壳。
- 当前运行目录以 `data/`、`wxbot_logs/`、`backups/` 为准；跨设备继续使用时，优先复制这些真实数据目录。
- 公开同步代码前，不要提交 `data/config/`、`data/prompt/`、`data/accounts/`、`wxauto_save/`、`wxbot_logs/`、`backups/` 等本地私有数据。

## 迁移与打包

如果你只是把当前项目迁到新的主工作电脑，并且之后还会继续开发和运行，优先直接整目录复制。

如果你需要一份相对干净的独立运行包，可以执行：

```powershell
.\打包发布.ps1
```

默认产物是 `dist/WXBot_Pro.zip`。脚本会打包运行所需代码、`data/system_prompts/` 和内置 Python 3.12 runtime，不会把 `data/config/`、`data/prompt/`、`data/accounts/`、`wxbot_logs/`、`backups/`、`docs/`、`tests/`、本地 `venv/` 或 Git 元数据带进去。

## 常见问题

### 图片识别为什么有时看不到图？

当前图片回复已按结构化图片消息处理。机器人会先尝试生成结构化图片摘要并写入本地记忆；支持视觉的回复接口随后会直接收图，不支持视觉的回复接口会使用这份摘要转述给主回复模型。

### 语音转文字是不是调用大模型？

不是。当前依赖微信自带的语音转文字能力。生产路径不调用 `msg.to_text()`；只有时长的私聊或已开启语音识别的群聊，会在约 5 秒、10 秒各用普通 `GetAllMessage()` 读取一份新快照。仍没有有效正文时静默忽略。

### PowerShell 里看到中文乱码怎么办？

这通常是 Windows 控制台编码显示问题，不代表源码损坏。开发和排查时请按 UTF-8 读取文件。
